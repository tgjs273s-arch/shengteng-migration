# 零秒识危 · 昇腾迁移与工程验证

本仓库围绕“零秒识危”项目，维护 Qwen3.5-0.8B 在华为昇腾 NPU 上的迁移、训练启动、性能数据整理和结果判定工具，同时保存作品说明、历史交付材料与实验依据。

当前开发重点是让工程链路可执行、失败可定位、结果可追溯。场景输入到实际模型识危输出的完整业务链路仍待核查和接通；本仓库尚不能作为已完成验收的识危应用。

  → P2 方案与训练配置生成

`65_scene.py`（场景入口）与 `62_reportability.py`（可报告性检查）是独立入口，目前尚未完整接入主流水线。

## 开始使用

### 1. 获取代码并确认工作位置

从 Gitee 仓库页面复制克隆地址：

```bash
git clone <仓库地址>
cd <克隆后的目录>
python 03_工具链/prepush_check.py --show-paths
```

最后一条命令只显示工具解析出的工作区路径。当前尚无经实机确认、适用于所有环境的一键依赖安装方案。

### 2. 在本机进行离线检查

Windows 可用于编辑、静态检查及部分 Python 测试；真实训练在 Linux 昇腾环境执行。完整 Skill 回归包含 Bash 子进程与 Linux 文件锁测试，建议在 Linux 或 WSL 中从仓库根目录运行：

```bash
PIPELINE_TEST_BASH=/usr/bin/bash python3 -m unittest discover -s 02_活副本_Skill/tests -p 'test_*.py' -v
python3 02_活副本_Skill/scripts/70_judge.py --selftest
```

本地 Python 需具备测试涉及的依赖（例如 PyYAML）；WSL 与 Windows 的 Python 环境彼此独立。这些测试使用隔离目录、测试替身或合成日志，不下载模型、不运行真实 NPU 训练。测试产物保留在被忽略的 `tmp/` 中。

### 3. 在华为昇腾环境做预检

先通过平台提供的 SSH 方式进入远端 Linux。看到本机 `C:\Users\...>` 提示符时仍未进入远端，不能在那里运行 NPU 检查命令。

在远端确认代码位置后执行：

```bash
npu-smi info
cd <远端仓库目录>/02_活副本_Skill
python3 scripts/05_preflight.py --json
python3 scripts/00_probe_env.py --quick --data-dir /workspace --out out/probe/env.json
```

`/workspace` 是示例目录，请按实际数据盘调整。还需确认 Python、PyTorch、torch_npu、CANN、MindSpeed-MM 的版本与兼容性，以及模型权重、数据路径和可用磁盘空间。环境开机、SSH 登录和训练可执行是三个不同的检查结果。

### 4. 条件满足后运行流水线

入口为：

```bash
bash scripts/run_from_zero.sh --quick --no-download \
  --data-dir /实际数据目录 \
  --msmm-dir /实际MindSpeed-MM目录 \
  --steps 5
```

这是预检通过、已有资产就绪后的短流程示例，**会尝试运行训练等阶段**，不是只读检查。`--no-download` 不会替代缺失的模型和数据；`--quick` 也不表示跳过训练。短运行可能因统计窗口或证据不足无法完成后续判定，不能当作正式评测。

主入口通过 P2 将 `--steps` 写入训练配置；若直接调用 `50_train.py`，应修改实际配置的 `train_iters`，其 `--steps` 仅用于提示。启动前核对生成的配置与算力开销。

更多参数、依赖关系与续跑要求见 [流水线执行与续跑](02_活副本_Skill/docs/流水线执行与续跑.md)。

## 产物与状态

主要产物位于 `02_活副本_Skill/out/`：

| 位置 | 内容 |
| --- | --- |
| `from_zero_report.md` | 本次阶段汇总 |
| `logs/` | 阶段执行日志 |
| `stage_state/` | 与代码、配置、依赖及产物关联的执行记录 |
| `plan/` | 迁移方案与训练配置 |
| `train/` | 训练日志及独立运行目录 |
| `judge/attempt-*/` | 单次判定的指纹、裁决及相关产物 |
| `judge/judge_summary.json` | 当前判定执行状态与本次目录引用 |

主入口退出码：`0` 表示所执行阶段通过，`1` 表示失败、超时或阻断，`2` 表示参数错误，`3` 表示部分验证。不能只根据文件存在判断成功。

P7 汇总中 `execution_state=COMPLETED` 表示请求的判定步骤完成，与裁决颜色是不同概念。默认可正常产出红/黄裁决；`--gate` 时按绿/黄/红返回 `0/3/4`。执行故障也可能返回 `3`，需结合汇总和日志判断。

公共 `out`、同一判定目录与同一本账本不支持并发运行。续跑必须有可核验的成功记录，旧文件本身不能作为复用依据。

## 协作与配置

- 使用自己的开发分支提交改动；修改当前主副本，不把历史交付目录误当开发入口。
- 每次重大改动同步更新 `AGENT.md`，记录原因、影响范围、验证结果和未验证项。
- `AGENT.md` 与源码一起提交；本地环境、凭证、模型权重、运行目录和整项目备份按 `.gitignore` 排除。
- SSH 密码、私钥、临时令牌不写入源码、文档或仓库地址。忽略规则无法过滤文档内部的凭证。
- 令牌代理已移除默认密钥，使用 `ZERO_RISK_BROKER_SECRET` 或显式 `--secret` 配置；缺失时拒绝启动。服务端与客户端应使用相同的新值。详见 [SSH 工具说明](05_SSH框架_ops/README_启动与重建清单.md) 顶部更新。
- 旧打包工具的 `--apply` 已禁用；不要直接执行历史覆盖式同步流程。
- 不批量删除文件或目录，保留必要诊断与历史证据。
