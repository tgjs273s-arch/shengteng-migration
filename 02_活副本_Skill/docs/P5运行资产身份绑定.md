# P5 运行资产身份绑定

`50_train.py` 可选地同时接收 `--assets-json`、`--migration-bundle`、`--migration-overlay`。三项必须成组提供；`--workdir` 是 T03 已安装的目标 checkout。省略三项保留旧独立 P5 用法，并在本次 `run.json` 记录 `asset_binding.state=UNBOUND`。主入口接入时不得把 `UNBOUND` 升为总验收通过。

受绑定模式在现有同日志 `fcntl` 锁内、启动 runner 前重新调用 T03 的 overlay/目标校验与 T05 的 HF、DCP、来源 JSON、转换 JSON及引用图片检查。它把有效配置中的 `training.load`、`model.model_name_or_path`、processor HF 路径、`dataset` 和 `dataset_dir/train2017` 对到 P4 路径。`dataset` 接受 P2 的单元素路径列表或旧单一路径字符串；多项和其他类型拒绝。相对配置路径按实际 MindSpeed-MM 工作目录解析；P4 记录的资产路径要求绝对路径，避免缺少 P4 工作目录时误解析。P4 路径和 manifest 路径只帮助定位，内容身份由摘要确定。P4 的 `assets.json`、migration manifest、目标源码和 DCP 转换收据均重新核对，不把 `readiness` 字符串单独作为证明。

每次 `runs/p5-*/run.json` 的 `asset_binding` 使用 `p5_asset_binding.v1`。`prelaunch` 与 `postrun` 包含 P4 attempt、assets JSON/manifest/转换收据 SHA-256、migration ID、目标 commit/源码摘要、实际路径，以及 HF/DCP 文件清单、LLaVA/训练 JSON 内容和顺序、引用图片清单摘要。`PRECHECK_OK` 仅表示前检已完成；后检与前检及 P4 声明一致时才写 `VERIFIED`。前检失败写 `PRECHECK_FAILED` 及本次 `train_integrity.json` 后返回非零，不启动 runner、不清空旧日志，`train_rc` 为 null。运行后缺失或漂移写 `DRIFTED`，训练完整性降为 `INCOMPLETE`。独立 P5 成功仍须满足原有返回码、日志完整性、源/有效配置及保存收据条件。

`train_integrity.json.asset_binding` 只保存状态、`run_record` 路径及其 SHA-256、assets SHA、migration ID、问题；没有反向引用完整性文件，避免循环哈希。`VERIFIED` 只证明本机当前纳入范围的内容前后相同，不证明官方同字节、真实导入类、NPU 数值、训练精度或模型重载。T07 在总入口未消费并验证本收据前继续保留 `runtime_asset_binding` 缺口。

本子步不改变 P5 的源/有效配置、日志、run ID、保存路径、锁及旧 CLI 语义。独立 QA 在 WSL 下对新增绑定 8/8、既有 checkpoint 隔离 7/7、runner 3/3、训练统计 10/10 完成离线回归，全部 rc=0、0 skip；QA 正整理仓库根目录下的 `docs/optimization/分步实施任务_20260928/records/T10_测试复核.md`。测试使用合成夹具；真实完整权重、数据与目标环境仍需后续运行验证。
