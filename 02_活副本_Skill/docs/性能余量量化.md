# 性能余量量化（Skill 方法篇）

> **这个 Skill 不只回答"跑通了吗 / 快不快"，还回答"慢在哪、还能快多少、上限是多少"。**
> 本文是这套方法的说明 + 一个**已实测的完整算例**（2026-09-17，boot `7bcced6f…`）。
> 方法与算例都可独立复跑；脚本：`54_three_point_fit.py` / `55_validate_prediction.py` / `56_profile_run.py`。

---

## 一、为什么不能只报一个"步时长"

迁移完成后，"每步 X ms"是一个**混合量**，里面至少叠了三种性质完全不同的成本：

| 成本 | 性质 | 可动的杠杆 |
|---|---|---|
| 每样本计算 | 随 batch 线性增长 | kernel 质量、融合、精度类型 |
| **每 micro-batch 固定开销** | 与样本数**无关**，每拆一个 micro-batch 就付一次 | 下发/图执行、通信重叠 |
| 每步固定开销 | 优化器/框架级，每步一次 | 优化器融合、梯度裁剪 |

**只测一个点永远分不开它们** —— 于是"该往哪优化"就只能靠猜。本方法用**批大小缩放**把三者分离。

## 二、方法：三点分离 + 预登记第 4 点（可证伪）

设 `t = F + gas × (f + a × mbs)`（`mbs`/`gas` 为配置项，`dp` 固定）：

| 点 | mbs | gas | GBS | 作用 |
|---|---|---|---|---|
| A | 4 | 1 | **8（官方几何）** | **唯一可参与官方对标** |
| B | 8 | 1 | 16 | 解 `a`（每样本计算） |
| C | 4 | 2 | 16 | 解 `f`（每 micro-batch 固定开销） |

⇒ `a = (tB − tA)/4`；`f = (tC − tA) − 4a`；`F = tA − (f + 4a)`

**关键纪律：三点三参数必然精确拟合，残差恒为 0 —— 所以三点本身不构成验证。**
必须再用**第 4 点**做**事前预测**（把预测值写进脚本、跑完再比对，`55_validate_prediction.py`）：
`tD = F + gas×(f + a×mbs)`，容差 ±10%。落在带内 → 模型可用；落带外 → **三点外推一律作废**。

**受控对照（不依赖模型）**：B 与 C 的 **GBS 相同**，差别只是"1 个 mbs=8 的 micro-batch"
vs "2 个 mbs=4 的 micro-batch" → `tC/tB` 直接给出**拆分本身**的代价。

## 三、第二步：用 profiler 把固定开销归因

Mspeed-MM 自带 profiler，**由配置项开启**（不需要改训练代码）：

```yaml
tools:
  profile:
    enable: true
    profile_type: static
    ranks: [0]                 # 只采 rank0，控制数据量
    static_param:
      level: level1
      with_cpu: true
      save_path: /abs/path/prof
      start_step: 15
      end_step: 20
      analyse_flag: true
```

产出 `<save_path>/<host>_<pid>_<ts>_ascend_pt/ASCEND_PROFILER_OUTPUT/step_trace_time.csv`，
五桶直接可用：**Stage / Computing / Communication / Communication(Not Overlapped) / Free**。

⚠ **profiling 会拖慢训练**：其 Stage **不得**与稳态步时长对标，**只能用比例**。

## 四、实测算例（2026-09-17，官方几何 mbs4/gas1/dp2，GBS=8）

**四点实测**（各 30 步，串行）：

| 点 | 几何 | 窗口 11–30 中位 |
|---|---|---|
| A | mbs4 gas1 **GBS=8** | **432.7 ms** |
| B | mbs8 gas1 GBS=16 | 715.5 ms |
| C | mbs4 gas2 GBS=16 | **862.4 ms** |
| D | mbs8 gas2 GBS=32 | **1354.3 ms**（预测 1428.0，带 [1285.2,1570.8]）→ **PASS** |

**解**：`a = 70.7 ms/样本`，`f = 146.9 ms/micro-batch`，`F = 3.0 ms/步`。
官方几何构成：432.7 = **146.9（34%）+ 282.8（65%）+ 3.0**。
受控对照：**C/B = 1.205×** —— 同样的总批量，只因拆成两个 micro-batch 就慢 20.5%。

**profiler 五桶**（同几何，rank0，第 15–20 步，均值）：

| 桶 | ms | 占 Stage |
|---|---|---|
| Stage | 458.93 | 100% |
| Computing | 312.52 | 68.1% |
| Communication（总） | 81.04 | 17.7% |
| **Communication(Not Overlapped)** | **40.32** | 8.8% |
| **Free** | **106.04** | 23.1% |

**互证（本文最重要的一行）**：

```
Free + Comm(未重叠) = 106.04 + 40.32 = 146.36 ms
四点拟合的固定开销 f              =  146.9  ms      → 吻合 0.4%（两条独立路径）
```

**发射密度**：`kernel_details.csv` 被采 5 步共 34,970 行 → **≈6,994 次发射/步**；
`106 ms ÷ 6,994 ≈ 15 µs/次`，与"下发间隙"量级自洽（**但未单独证明** Free 全为下发）。
`op_statistic.csv` 头部出现 `Transpose` **4,155 次 / 平均 23 µs**（≈831 次/步）——"多而小"算子的典型代表。

**上限（是上界，不是承诺）**：`432.7 − 106.0 − 40.3 = 286.4 ms`，相对官方 431.3 ms = **1.51×**
（与三点模型给的 285.8 ms 一致）。

## 五、使用这套方法时的硬规矩

1. **只有官方几何点（GBS=8）可对标**；其余点必须 `--allow-gbs-mismatch` 并标 `official_comparable=false`。
2. **三点不给结论**，必须先过第 4 点预测检验。
3. **固定开销 ≠ 可省时间**：`f` 是"量"，省不省得掉取决于它由什么构成（先做 profiler 归因）。
4. **profiling 的绝对时长不可对标**，只用比例。
5. **所有结论绑定 `identity.boot`**：本项目已实测同一 Skill 跨时段差 **2.27×**，
   跨时段外推一律无效（见坑 133 与 `<包>\10_交给Codex\06_关键证据\宿主差异发现_20260917.md`）。
6. **利用率类证据必须先做正对照**（坑 135）：采样器若从未在读数为"已知繁忙"时被验证过，
   它报的 0 既可能是真 0，也可能是取错设备/解析失配 —— 本轮 `54` 的 AICore 采样即因此作废，
   机制归因改走 profiler 五桶。
