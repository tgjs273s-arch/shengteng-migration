# 本次训练模型导出与重载

`scripts/66_export_model.py` 是独立入口；主流水线尚未接入。它不启动训练、下载或安装依赖。输入必须是 P5 本次 `runs/p5-*/`、P4 `migrator_assets.v2`、固定且已按 T03 补丁校验的 MindSpeed-MM checkout，和明确选定的保存步数。建议先在同一目录运行 `--inspect-only` 检查本次收据与 DCP 元数据；实际导出另起新的 `attempt-*`，不会覆盖前次结果。

```bash
python3 scripts/66_export_model.py \
  --train-run-dir /path/to/runs/p5-... \
  --assets-json /path/to/out/assets/assets.json \
  --target-checkout /path/to/MindSpeed-MM \
  --iteration 100 --out /path/to/out/model_exports --inspect-only

python3 scripts/66_export_model.py \
  --train-run-dir /path/to/runs/p5-... \
  --assets-json /path/to/out/assets/assets.json \
  --target-checkout /path/to/MindSpeed-MM \
  --iteration 100 --out /path/to/out/model_exports
```

每次写 `attempt-*/model_artifact.json`。`PREFLIGHT_ONLY` 仅说明本次配置、日志、P4 HF 来源和选定 DCP 元数据/文件清单通过检查；`EXPORTED_RELOAD_UNVERIFIED` 说明转换返回 0、导出索引、全分片头、参数键/形状/dtype、必要 processor/tokenizer 文件均通过检查。两者均不可供正式推理验收。只有 `RELOAD_VERIFIED` 且 `reload_verified=true` 可交给 T09 消费。失败写 `FAILED`、问题列表、转换返回码/日志 SHA 和已写出的部分文件清单，不清理原 checkpoint。

固定目标 `5b5505331924634da64e3d9a1925d02b10babe9f` 的 `Qwen35Converter.dcp_to_hf` 使用 `--dcp_dir`、`--save_hf_dir`、`--origin_hf_dir`，支持 `to_bf16` 和 `keep_origin_mtp_weights`，没有 `num_workers`。本入口固定 `to_bf16=false`、`keep_origin_mtp_weights=false`。原始 HF 索引有 488 键，其中 15 个 `mtp.*`；参考训练 MTP0。由于固定转换器从原索引选择 DCP 键，本入口在 `attempt-*/derived_origin` 创建临时非 MTP 资产视图，将 config 的 MTP 层数设为 0，索引缩为 473 键并按实际 DCP dtype/shape 重算 `total_size`。原始 HF 文件不改；原始和派生 config/index 各有独立 SHA。DCP 的实际模型键、shape、dtype 必须逐项对应，额外 tied `lm_head.weight` 只在 shape/dtype 对齐时允许；它的数值等价仍待真实重载比较。

真实重载比较需要固定框架和权重所在环境，加 `--verify-reload`。入口直接调用固定 checkout 的 `checkpoint.common.merge_dcp_to_hf.load_dcp_state_dict` 读取**选定的本次 DCP**，逐键核对实际张量，并使用目标 `model_register.get("qwen3_5")`、`ModelArguments`、`FeatureArguments` 和 `overwrite_transformer_config` 以 CPU eager/MTP0 构造目标模型。缺少的 tied head 仅从本次 DCP embedding 补为同一张量；若 DCP 自带 head，要求其值与 embedding 完全一致。目标模型以 `strict=True` 加载并确认无 meta 参数、嵌入与输出头共享存储。另一侧从导出 HF 目录 `from_pretrained(local_files_only=True)` 重载。两侧显式在 CPU FP32 执行，收据分别记录 DCP/导出存储 dtype 分布与实际执行 dtype；使用导出的本地 processor 编码固定中文输入并取 logits；HF 初始化缺/多/形状不符键会阻断。`round_trip/` 保存输入 JSON、两侧原始 float32 logits 文件、SHA 和比较指标，失败时也保留已完成文件。默认 `atol=rtol=0.05` 是工程冒烟阈值，不是官方精度规则；NaN/Inf 容差会在参数解析时拒绝。此代码路线尚未在完整权重/依赖环境上执行，需 T12 实测后才可能得到 `reload_verified=true`。

当前收据绑定 P5 run/config/log 哈希、完整训练步序列、隔离保存路径、选中 tracker 数值与 `iter_XXXXXXX` 的 `.metadata`、PyTorch DCP storage 引用区间、所有 payload 和 extra_state 文件 SHA。还要求 T10 的 `p5_asset_binding.v1` 为同一 run 的 `VERIFIED` 前后相同收据，核对 run/integrity 的路径和哈希，并以 `capture` 对当前 P4/assets、迁移和目标 checkout 再采集一次；`UNBOUND` 或漂移均阻断。派生视图只复制 P4 已纳入哈希清单的配置、processor/tokenizer 文件，不复制任意额外目录内容；若实际 processor 需要未纳入清单的资源，入口会失败并要求先扩充资产契约。它不能单靠旧 tracker、旧顶层产物或原 HF 权重宣布本次模型可用。`model_artifact.v1` 新版本只由这个独立入口产生；T10 负责后续主入口接线。回退可停止使用该入口并保留已产出的 attempt 证据，P5/P4 无需改动。

固定输入比较目前只覆盖文本 logits，不能代表视觉输入、NPU 性能或工业场景判断。
