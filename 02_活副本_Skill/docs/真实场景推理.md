# 对应模型产物的场景推理

入口：`scripts/65_scene.py`。本入口读取 T08 的 `model_artifact.v1`；需要其 `status=RELOAD_VERIFIED`、`reload_verified=true`、`post_export_identity_rechecked=true`。当前仓库没有已验证的真实产物或 NPU 推理结果。

```bash
python scripts/65_scene.py \
  --model-artifact /path/to/attempt/model_artifact.json \
  --model-dir /path/to/attempt/export_hf \
  --processor-dir /path/to/attempt/export_hf \
  --image /path/to/frame.png --sop /path/to/sop.txt \
  --device npu:0 --attention sdpa --max-new-tokens 160 \
  --out /path/to/scene-runs
```

`--sop` 是非空 UTF-8 文本文件。当前入口处理一张本地图像；视频/时序判断不在这个单图结果的测量范围。默认 NPU；`--device cpu --cpu-diagnostic` 仅用于明确的 CPU 诊断，收据不会标记真实 NPU 推理。模型与 processor 路径均须等于 T08 清单中导出的本地目录，不会使用远程模型兜底。`--attention` 只接受 `sdpa` 或 `eager`，实际配置与请求值不一致会失败。T08 的 CPU round-trip 比较与这里的 NPU 推理属于不同执行范围。

旧的 `python scripts/65_scene.py image.jpg --out out/scene` 可继续解析，位置图像等同 `--image`；两种写法同时提供会报参数错误。`--out` 省略时仍默认 `out/scene`。旧调用缺少产物清单和 SOP 时会在本次 attempt 写 `FAILED` 收据，需补上述新参数才可能执行真实推理。

每次调用在 `--out/attempt-*` 写 `inference_result.json`，包括模型产物/迁移/训练/checkpoint 身份、图像和 SOP 摘要、实际 NPU 卡号、`torch_npu` 版本或导入错误、模型与输入张量的设备集合、框架/模型类/源码摘要、注意力配置、生成参数、错误及耗时。真实生成后先保存 `generated_ids.json`、仅新增 token 解码的 `raw_generation.txt`，解析成功再写 `parsed_result.json`。输入、模型导出目录和产物收据在推理前后复核。`generate_synchronized` 在 NPU 上同步前后计时；加载与预处理字段是主机墙钟耗时，不当作设备阶段延迟，也不报告 TTFT。`business_validity=NOT_EVALUATED` 不表示业务正确率。

退出码 0 表示本次执行且 JSON 解析成功，包括合法的“无法判断”；3 表示前置、加载、执行、身份漂移、保存或解析失败；参数解析错误为 2。模型可用 `compliant=无法判断`、`bbox=null` 和非空原因说明证据不足，收据状态为 `EVIDENCE_INSUFFICIENT`。`PARSE_FAILED` 保留原始生成，`FAILED` 保留已形成的收据与问题。`real_inference_verified` 仅指已请求并确认 NPU 设备且完成真实生成；解析失败时仍可有 NPU 执行证据，但它不代表目标训练 kernel 数值正确或工业场景判断正确。`EXPECTED` 旧示例已从生产输出路径移除；没有图像、SOP、模型或 NPU 时不会打印示例判断。

固定目标源码中的 GDN/causal conv 及 decode/cache 路径仍受 T04 的实机数值验证约束。此入口使用导出的 HF 权重通过 Transformers 重载，收据明示框架边界，不把 HF 推理等同于 MindSpeed-MM 训练目标 kernel 的执行。
