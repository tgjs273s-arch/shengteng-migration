# P4 资产完整性与身份

`scripts/40_prepare_assets.py` 保留原 CLI，并增加成对的 `--migration-bundle`、`--migration-overlay`，输出 `assets.json` 升为 `migrator_assets.v2`。P4 调用 T03 的 overlay 与目标 checkout 校验器，记录经校验的 `migration_id`、manifest SHA 和目标提交；未提供时标为 `local_complete_migration_unbound`，不自行推算身份。`--no-download` 只读取本地文件，不调用下载、依赖安装或转换。缺件写入 `missing_required`，返回 3；`readiness=local_complete_official_unverified` 只说明本地所检查的资产齐备，**不代表官方同字节或模型可重载**。

## 权重与转换

HF 检查复用 T03 `_qwen35_weights.py` 对固定 0.8B config/index/processor 元数据、488 个索引键、分片头、关键形状和 tied `lm_head` 源的判据。另要求可解析的 `tokenizer.json`，逐文件计算全部索引分片、config、index、preprocessor、tokenizer 配置与 tokenizer 内容 SHA-256。清单记录 `metadata_revision=2fc06364715b967f1860aea9cf38778875588b17`、实际本地文件哈希；完整上游 payload revision 和与官方权重同字节状态为未验证。下载仅通过 [Hugging Face 官方 `snapshot_download` 接口](https://huggingface.co/docs/huggingface_hub/guides/download) 请求 `repo_id=Qwen/Qwen3.5-0.8B`、该固定 HF commit 和本地目标目录；缺 `huggingface_hub` 或下载失败即保留缺件，不安装依赖、不回退浮动版本。HF 与 ModelScope 仓库的 revision 映射未验证，故不将 HF SHA 传给 ModelScope 镜像。

DCP 检查要求 `latest_checkpointed_iteration.txt=release`、非空 `release/.metadata` 和实际非空 `.distcp` payload 文件，逐文件记录大小与 SHA-256。使用 PyTorch `FileSystemReader.read_metadata()` 读取 `storage_data`，逐条核对 payload 相对路径、偏移、长度与实际文件大小；损坏、缺失、越界均不可就绪。缺 PyTorch 读取器标为 `metadata_unverified`，也不可就绪。已有 `migration_conversion_receipt.json` 必须是 v3，并同时绑定 HF 本地文件清单摘要、DCP 文件清单摘要、固定目标 `5b5505331924634da64e3d9a1925d02b10babe9f`、converter 补丁与 tied 映射，以及提供时的 T03 migration ID/manifest SHA。旧 v2 只绑定元数据，作为不足证据保留，不自动重写或据此跳过转换；不完整目录不覆盖。参数完整性和真实重载仍由 T08 验证，`reload_verified=false`。

P4 不重算 T03 `migration_id`；主入口接入 T03 manifest 时直接传入 bundle 与 overlay。仅有 T03 固定小元数据与 safetensors header 不能替代权重 payload 身份。

## 数据

本地 LLaVA 输入 JSON 和转换 JSON 均按固定转换器的实际列表结构核对；空列表、空对话及坏消息格式拒绝。转换 JSON 中 `images` 为零张或多张图片列表，`messages` 的角色为 `user` 或 `assistant`。图片引用必须位于 COCO `train2017/` 内、文件非空可读，并经 Pillow 完整解码。缺少 Pillow 时图片仅记字节身份、`image_decode_verified=false`，资产不能升为本地齐备。`data_identity.image_inventory` 保留每张被引用图片的路径、大小、哈希和解码结果，聚合摘要用于下游快速比对。原始/转换 JSON 的字节与样本顺序身份复用 `sk04_judge/scripts/data_id.py`。

数据转换脚本来自固定目标提交 `5b5505331924634da64e3d9a1925d02b10babe9f` 的 [`llava_instruct_2_mllm_demo_format.py`](https://github.com/Ascend/MindSpeed-MM/blob/5b5505331924634da64e3d9a1925d02b10babe9f/mindspeed_mm/fsdp/tools/data_tool/llava_instruct_2_mllm_demo_format.py)，本轮只读取得脚本 SHA-256 `2901488ed98ab162487200ff28f7bc8367d72304a9c57fc878ce0b2c3cdc2e95`。P4 实际转换前核对本地脚本摘要，记录 `--llava_json_path`、`--coco_path`、`--output_json_path`、返回码与每次尝试的完整日志路径/哈希；返回码为零也必须重新核对新产物与图片。不将大小/样本数/图片数相同升级为官方数据同字节。没有可信官方内容摘要时，`official_data_identity.status=unverified`，但本地身份可供 T07/T10 比对。
