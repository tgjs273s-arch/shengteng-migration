# Qwen3.5-0.8B 固定源码迁移

当前脚本的工程输入固定为 Transformers `fc9137225880a9d03f130634c20f9dbe36a7b8bf`、MindSpeed-MM `5b5505331924634da64e3d9a1925d02b10babe9f`（2026-09-29 核到的 `26.1.0` 分支提交）和 Qwen/Qwen3.5-0.8B 元数据 `2fc06364715b967f1860aea9cf38778875588b17`。用户提供的六页《数据及训练配置、脚本.pdf》要求 `git checkout 26.1.0`，未给材料编制时的不可变提交；其中训练示例为 4B。0.8B revision 是本工程单独锁定的迁移输入，不能称为 PDF 指定。旧 `6c45b4869f9938892b982a203cc121803c345db2` 原型的静态重放及 13 项离线回归记录继续保留，不能迁移为新版本验证结果。仓库旧 `refs/` 只供 P1 AST 分析，其字节内容与固定 GPU 提交不同。

## 实际迁移与复用

目标框架在上述提交中已有完整 `Qwen3_5ForConditionalGeneration`、`@model_register.register("qwen3_5")`、视觉/文本 forward、GDN 和 `Qwen35Converter`。本项目不复制或换名声明这些实现为自产。`22_migrate_qwen35.py` 对真实 GPU 和目标文件逐字节核对，产出上游模型差异、目标 converter 的单处项目补丁及 `migration_manifest.json`。该补丁在**逐分片转换开始前**检查 tied 映射源键，防止源键缺失时上游 converter 静默跳过。P4 同时改用 `Qwen35Converter` 并显式传入 `lm_head.weight` ← `model.language_model.embed_tokens.weight`；这是 0.8B 权重索引确实缺少 `lm_head.weight` 时的必要适配。

源码入口在 `02_活副本_Skill/` 运行。`fetch` 仅获取三个 GPU 源文件、九个目标源码/配置文件和四个小型模型元数据文件，不获取 safetensors 权重。目标九项包含模型、ModelHub、注册器、MTP、causal conv、模型与特性参数、converter 以及 4B 示例配置；4B 文件用于来源追溯，不作为 0.8B 训练配置。网络抓取需按运行环境权限执行；也可事先把这些小文件按 `22_migrate_qwen35.py` 的 `FILES` 路径置于新 bundle，`apply` 逐个校验 SHA-256。不要覆盖旧 6c45 bundle/overlay。

```bash
python3 scripts/22_migrate_qwen35.py fetch --bundle /path/to/t03-bundle
python3 scripts/22_migrate_qwen35.py apply --bundle /path/to/t03-bundle --out /path/to/t03-overlay
```

`apply` 只写 overlay，不改 bundle。输出包括 `overlay/checkpoint/vlm_model/converters/qwen3_5.py`、`qwen35_converter.patch`、`upstream_model_diff.patch` 和 `migration_manifest.json`。同样输入重复执行逐字节幂等；不同源文件、目标文件或已存在的不同产物拒绝覆盖。若需将补丁应用到**另备的、无其他 tracked 修改的目标 checkout**，先核对其 HEAD，再运行：

manifest 的关键状态示意（仅展示字段，**不是运行产物**）：

```json
{"schema":"qwen35_migration.v1","source":{"commit":"fc9137225880a9d03f130634c20f9dbe36a7b8bf"},"target":{"commit":"5b5505331924634da64e3d9a1925d02b10babe9f"},"execution_state":"STATIC_APPLIED_RUNTIME_PENDING","complete_weights_verified":false,"npu_numeric_verified":false}
```

```bash
python3 scripts/22_migrate_qwen35.py install --bundle /path/to/t03-bundle \
  --overlay /path/to/t03-overlay --target-checkout /path/to/MindSpeed-MM
```

`install` 从固定原始文件及本项目补丁代码重算预期输出，不信任 manifest 自报哈希；每次（包括幂等重放）检查目标 HEAD、模型/注册文件和仅有的 converter 差异。原始目标文件保留在 Git 提交内。不要对共享生产 checkout 直接安装。回退可在该隔离 checkout 针对唯一 converter 文件恢复固定目标提交；保留 manifest 和 diff 作为本次操作记录。

若固定目标的 Python 依赖已备齐，可在隔离 checkout 中进一步检查注册、meta 模型实例化和 forward 签名；带本地完整 HF 权重时还会逐键比较模型 `state_dict` 形状，带完整 processor 目录时尝试本地加载。缺少依赖返回 4，绝不把静态步骤升级为运行通过。

```bash
python3 scripts/22_migrate_qwen35.py runtime --bundle /path/to/t03-bundle \
  --overlay /path/to/t03-overlay --target-checkout /path/to/MindSpeed-MM \
  --out /path/to/t03-runtime [--hf-dir /path/to/Qwen3.5-0.8B-hf] \
  [--processor-dir /path/to/Qwen3.5-0.8B-hf]
```

运行结果为独立的 `runtime_validation.json`。26.1.0 目标注册器装饰后会返回类；runtime 仍与 `ModelHub` 一样从 `model_register.get("qwen3_5")` 取得模型类。入口核对实际导入的模型、ModelHub、注册器及模型/特性参数模块 `__file__` 与固定 checkout 的精确路径。meta 构造调用目标类的 `overwrite_transformer_config(config, model_args, feature_args)`，将 GDN/causal conv 设为 eager，MTP 设为 0；这些覆盖仅服务于不执行算子的 meta 检查，不能代表训练配置或目标 Triton 已运行。MTP=0 依据用户提供的 Triton 参考日志第 90/91 行，日志 SHA-256 已写入 manifest。无 `--hf-dir` 时 `state_dict_shapes=pending`、`ignored_checkpoint_keys.keys=null`；有完整本地权重头时列出从源头实际检查到、但未映射进禁用 MTP 的 meta 模型的每个 `mtp.*` 键及 tied head 排除项。无 `--processor-dir` 时 `processor=pending`。已确认的依赖导入缺失返回 4；其他模型构造错误返回 3。这项检查不执行 forward 数值计算、DCP 重载或 NPU 训练。

## 参数与验证层级

固定 0.8B 索引列出 488 个键；有 `model.language_model.embed_tokens.weight` 而无 `lm_head.weight`，并列出 15 个 `mtp.*` 源键。`_qwen35_weights.py` 核对 config/index/processor/tokenizer 固定字节哈希，再逐个读取本地 safetensors **头部**，要求全部索引键覆盖、分片归属正确、形状/dtype/offset 合法，并核对 embedding、视觉 Conv3d 和首层 GDN Conv1d 三项关键形状。上游 26.1 converter 对该非 MoE 0.8B 的 MTP 键按普通源键传入 DCP；P4 收据记录 15 个源键和参考训练的 MTP=0，但 DCP 实际键及重载仍待验证，不能将源索引视为已加载训练参数。头部核查不读取 tensor payload，也不证明参数与目标模型完整匹配。目标模型的 `^mtp.*` 忽略规则仅用于明确的额外键，不扩展到其他缺键。

P4 转换前还要求实际 MindSpeed-MM checkout 为该固定提交、模型与注册文件原样、converter 为本项目唯一补丁，身份写入 `assets.json.conversion`。`all_weight_headers_checked` 表示索引中的**全部键**有合法的 shape/dtype/无重叠且字节跨度正确的分片头部，但只把 embedding、视觉 Conv3d 与首层 GDN Conv1d 三项形状和模型配置公式相互核对；其余参数与目标模型的形状是否一致须运行 `runtime --hf-dir`。转换成功后 P4 保存 `migration_conversion_receipt.json`，绑定源配置/索引、目标提交/补丁及 DCP `.metadata` 摘要。既有 DCP 只有 tracker 和 `.metadata`、没有同源收据时标 `existing_unverified` 并不能令 `ASSETS_OK`；残留半成品目录不会被覆盖。`converted_structure_only` 和有收据的 `existing_verified_receipt` 均只证明转换身份与 DCP 结构，完整 tensor payload 哈希、模型真实重载由 T05/T08 核对。GDN 数值与 NPU 训练由 T04/T12 验证。`migration_manifest.execution_state=STATIC_APPLIED_RUNTIME_PENDING` 即使命令返回 0 也不得解释为训练或数值通过。

失败示例：GPU/目标源码摘要不符、目标 checkout 提交不符、固定 metadata 错版、缺 safetensors 分片、缺 tied embedding、关键形状错误、converter 退出非零或 DCP tracker 已出现但 `.metadata` 缺失，均不能生成完整成功声明。`22` 返回 0 表示请求的源码步骤完成、3 表示身份/输入/补丁失败；`fetch` 网络错误也失败。P4 沿用既有退出码，在转换受阻时通过 `checks` 和资产完整性返回 3。
