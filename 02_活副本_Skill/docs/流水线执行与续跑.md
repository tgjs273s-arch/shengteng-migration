# 主入口失败处理与续跑说明

适用入口：`scripts/run_from_zero.sh`。实际模型和训练仍在华为昇腾 NPU 的 Linux 环境运行；本次本地测试只验证编排行为。

## 四流程接线状态（2026-09-29）

主入口支持 `--flow diagnostic|reference|candidate|inference`，无该参数的旧调用按 `diagnostic` 处理。`diagnostic` 保持 P2 默认参考角色，可不传迁移 bundle；这时 P3/P4/P5 的未绑定证据及 P7 规则缺口使总结果为 PARTIAL。`reference` 和 `candidate` 必须成组提供 `--migration-bundle`、`--migration-overlay`。`--msmm-dir` 指向安装了 T03 补丁的固定目标 checkout；`--asset-model-dir` 确定 P2 HF/DCP 路径和 P4 权重目录。旧 `--data-dir` 仍是数据父目录，P2 接收 `<data-dir>/coco` 作为图片根目录，P4 接收父目录。

`reference` 不构造 A/B；`candidate` 还要求 `--ab-summary`、`--noise-summary`、`--baseline-variant` 和 `--candidate-variant`。A/B 摘要可包含多次运行，现有 59/63 没有与本次 P5/P7 逐运行对应的来源收据；P8 调用 62 计算配对性能，固定 `run_validity=UNVERIFIED`、`accuracy_validity=UNVERIFIED`，不得据单次 P7 的 `VALID_MEASUREMENT` 填精度 OK 或宣布可采纳。正式规则仍 `RULE_PENDING`。

模型导出须显式 `--export-model --export-iteration N`，P9 调用 `66_export_model.py --verify-reload`，只接受当前 attempt 的 `model_artifact.v1` 为 `RELOAD_VERIFIED`。训练流程推理须同时请求本次导出，再以 `--run-inference --image FILE --sop FILE` 启用 P10；P10 只消费本次 P9 导出，禁止接入另一训练 run 的外部模型。已有模型使用独立 `--flow inference`，只运行 P10，不执行 PRE–P9、训练或下载；必须提供 `--model-artifact FILE --model-dir DIR --processor-dir DIR --image FILE --sop FILE`，前三者须指向同一份经 T08 重载验证的本地 HF 导出。设备默认 `npu:0`；CPU 仅供显式 `--device cpu --cpu-diagnostic`。可选 `--attention sdpa|eager` 与 `--max-new-tokens 1..4096`。未请求的模型/推理层记为 `NOT_RUN`。

P2 的参考配置固定绑定仓库 `officialB` 对应的 Triton 历史日志身份。主入口 `--baseline`/`--baseline-log` 虽传给 P7，但参考/候选流程受支持的组合仅为 `officialB` 与同字节的 `examples/train/official_baseline.log`；改传其他基线不会改变 P2 来源，P7 会给出身份或可比性缺口，不能按同一参考流程宣称通过。需要其他基线时须先建立对应的 P2 来源契约。

主入口把 P2 的 `reference_config.yaml/config_manifest.json`、P5 本次 `runs/p5-*` 配置快照/完整性/run 收据、P7 本次 `attempt-*`、P9 导出 attempt、P10 推理 attempt 的文件纳入阶段哈希。P10 复核 T08 模型身份、导出文件清单、图像/SOP、原始 token/文本及解析文件；`EXECUTED_PARSED` 和 `EVIDENCE_INSUFFICIENT` 都只表示执行与解析状态，业务有效性仍为 `NOT_EVALUATED`。P6 读取 P5 有效配置和运行 world 推导 GBS，并传给 `95_extract_series.py --expected-gbs`；其 `train_performance.v2` 将前 200 条中的末 100 条算术均值与 50–100 的 51 点诊断窗口分开。完整 100 条已满足前者，不要求改成 200 步。P3 有 contract-only 时继续 PARTIAL。总报告和机器可读分层汇总分开记录执行、完整性、可比性、数值、性能、模型与推理；证据门未闭合时入口返回 3。

## 阶段状态与退出码

阶段执行成功需要同时满足：子进程返回符合该阶段契约、业务判据满足、必需输出非空且本次已更新。P6 的短诊断统计可用退出码 3 表示不完整选择并保持 PARTIAL；P8 的 3/4/5 分别保留 62 的受阻/未达标/无法判定语义，成功写出本次报告也只计 PARTIAL。其余阶段的失败返回码不能被旧产物掩盖。失败时保留日志与原文件，不删除旧产物；旧文件不能充当本次成功证据。

| 状态 | 含义 |
|---|---|
| PASS | 阶段执行及产物校验通过，不代表完整模型精度或性能收益已验证 |
| PARTIAL | 阶段产物有效，但 P3 contract-only、短诊断统计、规则或采纳证据仍有明确缺口 |
| FAIL | 退出码、业务判据、产物新鲜度或一致性检查失败 |
| TIMEOUT | 阶段命令超时 |
| BLOCKED | 前置阶段失败或缺少可验证的前置产物，本阶段未执行 |
| RESUMED | 成功记录及本地产物复核通过，本阶段未重新执行；原有部分验证边界仍计入总报告 |

入口退出码：0 为本次所执行/复用阶段无失败且无部分验证；1 为存在失败、超时或阻塞；2 为无效参数/入口错误；3 为无失败但仍存在部分验证。P7 的业务裁决需要另行阅读 judge_summary.json，不能将入口 0 当作精度已对齐或优化已通过采纳。

## 依赖与独立诊断

P2 依赖 P0/P1，P3 和 P4 依赖 P0，P5 依赖 PRE/P2/P3/P4，P6 依赖 P5，P7 依赖 P2/P4/P5；候选 P8 依赖 P5/P6/P7，模型 P9 依赖 P4/P5。同次请求导出和推理时 P10 依赖本次 P9；独立推理验证显式 T08 产物、模型目录及场景输入。例如 P1 失败时，P2/P5/P6/P7/P8/P9 被阻断，独立的 P3/P4 诊断仍可运行。

P3 的部分验证允许训练诊断继续，以采集实际问题，但总结果保持部分验证，不能作为完整正确性验收。

## 续跑条件

成功记录位于 `out/stage_state/<stage>.json`，绑定代码/配置/参考源码摘要、入口参数、上游执行身份、输出及日志哈希。每次执行前先写 RUNNING，使中断或失败后的旧成功记录失效。输出缺失、被修改、代码或参数变化均会拒绝复用。

- `--resume`：检查成功记录后复用；PRE/P0/P4 仍重新探测/检查。它们的新执行身份会使依赖它们的缓存失效，因此这是保守复用，并非保证跳过训练。
- `--from P4`：前置阶段必须已有可核验成功记录，否则标为 BLOCKED。升级前留下的裸产物没有这些记录，需要从 PRE 重新跑一次；不会自动启动用户要求起点之前的训练或下载。
- `--force`：关闭 --resume，但不绕过 --from 的前置校验。

RESUMED 只证明纳入 receipt 的来源与一致性，不证明当前硬件可用。新参数身份包含迁移 bundle/overlay、基线日志、A/B 与底噪文件的内容摘要；严格流程复用 P5 时还重读当前资产和目标源码，与运行前后快照比较。P4 在 `--resume` 仍重跑。更换 NPU 环境、数据、权重或外部 MindSpeed-MM 版本后，仍应从 PRE 重新执行。

当前 out 仍是单工作目录，暂不支持两个主入口同时运行。P5 的每次运行目录和日志隔离已实现；这不提供 NPU 调度或端口预留。

## 本地回归

在 Linux/WSL，工作目录为 Skill 根目录时运行：

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

完整编排回归须使用 Linux/WSL 原生 Python 与 Bash。Windows 可运行适用的离线 Python 子集；`bash.exe` 可能只是 WSL 启动入口，不能据其存在推定能驱动 Windows Python 测试。编排测试用假阶段替换模型执行，覆盖中途失败、旧产物、部分验证、超时、独立诊断和 --from 复用。测试目录保留于仓库根目录 `tmp/` 以便排查，不自动递归删除。


## 自定义数据目录

主入口的 --data-dir 相对路径以 Skill 根目录为基准解析为绝对路径，再传给 P0/P2/P4/P7。配置生成使用该目录下的 output_llava_coco_data.json 及 coco 子目录，避免训练继续使用模板中的 /root/data。

入口参数按 shell 边界引用；P2 数据和权重路径通过 JSON 兼容的 YAML 字面量写入并回读检查，避免空格、单引号、冒号或 # 改变配置含义。P4 的下载参数和转换命令同步处理路径引用，unzip 使用参数列表。

本地测试验证了参数传递和配置生成，真实数据下载、转换和 NPU 训练仍需在华为环境验证。路径正确不代表数据已存在或内容已经通过评估。

## 训练运行与判定输出隔离（2026-09-23）

P5 每次在 `--log` 父目录的 `runs/p5-*` 中保留 `runner.sh`、`runner.log`、`run.json`。前后台均按实际子进程退出码判定；后台保留 nohup/独立 session。Linux 文件锁阻止两个 P5 同时使用同一训练日志，进程退出后锁自动释放，残留 `.lock` 文件不表示仍在运行，也不要通过删除锁文件解除锁。查看本次打印的 PID、运行目录及训练日志排错。

`--log` 是本次输出目标，开始执行时会清空旧内容；需要保留历史训练日志时，每次传入不同路径。运行目录和测试产物不自动清理。公共主入口 `out` 仍只支持单任务；直接运行多个 P5 时仍须自行分配 NPU 与端口，本轮没有解决设备调度或端口预留。

P7 每次在 `--out/attempt-*` 创建新目录，子工具只读取本次目录中的文件。要求子工具成功退出、JSON schema 有效、裁决字段完整；指定账本时还要求追加成功确认。`--registry` 与 `--tag` 必须成对提供；账本失败使整个请求返回 3，但本次已生成的证据仍保留，不回滚已完成的外部写入。账本引用本次目录，避免后来运行覆盖原证据。

顶层 `judge_summary.json` 包含 `execution_state` 和 `attempt_dir`：RUNNING 表示尚未完成，FAILED 表示已捕获工具失败，COMPLETED 表示所请求的判定步骤完成。异常中断可能留在 RUNNING。全部成功后才更新顶层兼容 JSON，汇总最后写入；失败时旧文件可保留，必须同时检查退出码和当前汇总，不能按“文件存在”判成功。历史 `loss_compare.csv` 也不能当作本次结果，当前对比产物以 attempt_dir 为准。

默认返回 0 仅代表判定产出完成，红/黄裁决也可正常产出；`--gate` 保留 0 绿、3 黄、4 红。执行故障同样可返回 3，应结合 execution_state 区分。P7 相同输出目录及同一本账本的并发写入尚不支持。
