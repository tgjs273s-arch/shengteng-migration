# 主入口失败处理与续跑说明

适用入口：`scripts/run_from_zero.sh`。实际模型和训练仍在华为昇腾 NPU 的 Linux 环境运行；本次本地测试只验证编排行为。

## 阶段状态与退出码

阶段执行成功需要同时满足：子进程退出码为 0、阶段业务判据满足、必需输出非空且本次已更新。失败时保留日志与原文件，不删除旧产物；旧文件不能充当本次成功证据。

| 状态 | 含义 |
|---|---|
| PASS | 阶段执行及产物校验通过，不代表完整模型精度或性能收益已验证 |
| PARTIAL | P3 中仍存在 contract-only 项，未完成全部算子执行验证 |
| FAIL | 退出码、业务判据、产物新鲜度或一致性检查失败 |
| TIMEOUT | 阶段命令超时 |
| BLOCKED | 前置阶段失败或缺少可验证的前置产物，本阶段未执行 |
| RESUMED | 成功记录及本地产物复核通过，本阶段未重新执行；原有部分验证边界仍计入总报告 |

入口退出码：0 为本次所执行/复用阶段无失败且无部分验证；1 为存在失败、超时或阻塞；2 为无效参数/入口错误；3 为无失败但仍存在部分验证。P7 的业务裁决需要另行阅读 judge_summary.json，不能将入口 0 当作精度已对齐或优化已通过采纳。

## 依赖与独立诊断

P2 依赖 P0/P1，P3 和 P4 依赖 P0，P5 依赖 PRE/P2/P3/P4，P6 依赖 P5，P7 依赖 P2/P4/P5。例如 P1 失败时，P2/P5/P6/P7 被阻断，独立的 P3/P4 诊断仍可运行。

P3 的部分验证允许训练诊断继续，以采集实际问题，但总结果保持部分验证，不能作为完整正确性验收。

## 续跑条件

成功记录位于 `out/stage_state/<stage>.json`，绑定代码/配置/参考源码摘要、入口参数、上游执行身份、输出及日志哈希。每次执行前先写 RUNNING，使中断或失败后的旧成功记录失效。输出缺失、被修改、代码或参数变化均会拒绝复用。

- `--resume`：检查成功记录后复用；PRE/P0/P4 仍重新探测/检查。它们的新执行身份会使依赖它们的缓存失效，因此这是保守复用，并非保证跳过训练。
- `--from P4`：前置阶段必须已有可核验成功记录，否则标为 BLOCKED。升级前留下的裸产物没有这些记录，需要从 PRE 重新跑一次；不会自动启动用户要求起点之前的训练或下载。
- `--force`：关闭 --resume，但不绕过 --from 的前置校验。

RESUMED 只证明本地产物的来源与一致性，不证明当前硬件可用，也不重新读取外部模型权重或数据内容。更换 NPU 环境、数据、权重或外部 MindSpeed-MM 版本后，应从 PRE 重新执行，不用 --from 重用旧环境结果。

当前 out 仍是单工作目录，暂不支持两个主入口同时运行。训练脚本的共享 /tmp 文件问题 F08 仍待独立修复。

## 本地回归

在 Linux/WSL，工作目录为 Skill 根目录时运行：

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Windows Git Bash 可通过 `PIPELINE_TEST_BASH` 指定 Bash 完整路径，再使用本地 Python 执行同一命令。测试用假阶段替换模型执行，覆盖中途失败、旧产物、部分验证、超时、独立诊断和 --from 复用。测试目录保留于仓库根目录 `tmp/` 以便排查，不自动递归删除。


## 自定义数据目录

主入口的 --data-dir 相对路径以 Skill 根目录为基准解析为绝对路径，再传给 P0/P2/P4/P7。配置生成使用该目录下的 output_llava_coco_data.json 及 coco 子目录，避免训练继续使用模板中的 /root/data。

入口参数按 shell 边界引用；P2 数据和权重路径通过 JSON 兼容的 YAML 字面量写入并回读检查，避免空格、单引号、冒号或 # 改变配置含义。P4 的下载参数和转换命令同步处理路径引用，unzip 使用参数列表。

本地测试验证了参数传递和配置生成，真实数据下载、转换和 NPU 训练仍需在华为环境验证。路径正确不代表数据已存在或内容已经通过评估。

## 训练运行与判定输出隔离（2026-09-23）

P5 每次在 `--log` 父目录的 `runs/p5-*` 中保留 `runner.sh`、`runner.log`、`run.json`。前后台均按实际子进程退出码判定；后台保留 nohup/独立 session。Linux 文件锁阻止两个 P5 同时使用同一训练日志，进程退出后锁自动释放，残留 `.lock` 文件不表示仍在运行，也不要通过删除锁文件解除锁。查看本次打印的 PID、运行目录及训练日志排错。

`--log` 是本次输出目标，开始执行时会清空旧内容；需要保留历史训练日志时，每次传入不同路径。运行目录和测试产物不自动清理。公共主入口 `out` 仍只支持单任务；直接运行多个 P5 时仍须自行分配 NPU 与端口，本轮没有解决设备调度或端口预留。

P7 每次在 `--out/attempt-*` 创建新目录，子工具只读取本次目录中的文件。要求子工具成功退出、JSON schema 有效、裁决字段完整；指定账本时还要求追加成功确认。`--registry` 与 `--tag` 必须成对提供；账本失败使整个请求返回 3，但本次已生成的证据仍保留，不回滚已完成的外部写入。账本引用本次目录，避免后来运行覆盖原证据。

顶层 `judge_summary.json` 包含 `execution_state` 和 `attempt_dir`：RUNNING 表示尚未完成，FAILED 表示已捕获工具失败，COMPLETED 表示所请求的判定步骤完成。异常中断可能留在 RUNNING。全部成功后才更新顶层兼容 JSON，汇总最后写入；失败时旧文件可保留，必须同时检查退出码和当前汇总，不能按“文件存在”判成功。历史 `loss_compare.csv` 也不能当作本次结果，当前对比产物以 attempt_dir 为准。

默认返回 0 仅代表判定产出完成，红/黄裁决也可正常产出；`--gate` 保留 0 绿、3 黄、4 红。执行故障同样可返回 3，应结合 execution_state 区分。P7 相同输出目录及同一本账本的并发写入尚不支持。
