# P2 参考与候选配置

`scripts/20_plan_migration.py` 默认生成 `reference` 角色。独立参考模板 `config/templates/qwen3_5_0_8B_reference.yaml` 的几何和已核对开关取自仓库保存的 2026-07-24 Triton 日志，绑定基线 ID `qwen35-0p8b-triton-20260724-100step-v1` 及当前日志字节哈希。使用 `--config-role candidate` 才采用 P0 的环境推荐档。两种角色均输出 `out/plan/train_config.yaml`、`reference_config.yaml`、`config_manifest.json` 和 `migrate_plan.md`；具体位置由 `--out` 决定。

例如从 Skill 根目录运行：

```bash
python3 scripts/20_plan_migration.py --env out/probe/env.json --points out/analyze/migrate_points.json --out out/plan
python3 scripts/20_plan_migration.py --config-role candidate --env out/probe/env.json --points out/analyze/migrate_points.json --out out/candidate-plan
```

`config_manifest.json` 的 `role`、`baseline_id`、`effective_config.sha256`、`reference_config.sha256`、`source_inputs`、`geometry` 和 `differences_from_reference` 记录配置身份。差异逐字段比较有效 YAML 与独立参考模板，包含 `--steps`、路径覆盖、自定义模板和字段缺失/null 的区别。`reference_feasibility=blocked` 表示已知探测档无法支持参考几何/后端或需要 CANN 工作区；P2 保留诊断产物并返回 3，阻断旧主入口继续训练。探测字段缺失则记 `unknown`，不能称已适配。P5 仍按实际 world 与 GBS 做启动前检查。

参考日志未给出完整模型、权重和数据字节身份，也未给出本轮正式精度规则。清单中的 `verified_reference_fields` 仅列本轮逐项核对的日志字段；其余完整参考模板叶字段均列入 `template_default_fields_unverified`，其中包括 `training.save_format=auto`。`RULE_PENDING` 不能解释为精度通过。参考日志 LF 与 CRLF 的字节哈希不同，P2 检查当前仓库副本的 LF 字节。旧 `officialA`、`officialB` 名称不在本脚本自动解析。资产内容身份由 P4 记录，正式数值对比由 T07 判定。

新增的 `config_manifest.json` 与 `reference_config.yaml` 尚未纳入 `_stage_state.py` 的 P2 必需输出列表。主入口续跑和下游强制消费由 T10 在集成阶段处理；在此之前，单独复用 P2 时应核对它们与 `effective_config.sha256`。
