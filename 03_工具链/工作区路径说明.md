## 核对检查目标

```powershell
python 03_工具链/prepush_check.py --show-paths
python 03_工具链/prepush_check.py --list
python 03_工具链/prepush_check.py --only G12,G28
```

共享参数：`--root`、`--skill`、`--tools`、`--deliverables`、`--evidence`。组件相对路径相对于 root 解析，绝对路径直接使用。显式 --root 重置组件默认位置；可再显式覆盖组件路径。

```powershell
python 03_工具链/prepush_check.py --root "D:/另一份项目" --evidence "证据目录" --show-paths
```

最终路径通过 `ZERO_RISK_ROOT`、`ZERO_RISK_SKILL`、`ZERO_RISK_TOOLS`、`ZERO_RISK_DELIVERABLES`、`ZERO_RISK_EVIDENCE` 传给子工具。直接运行工具时也可以使用这些环境变量；命令行显式路径优先。读取不存在的目标时应报告缺项，不会偷偷回退原作者目录。

覆盖工具：prepush_check、check_report_pdf、safe_pack_sync、evidence_manifest、check_pitfalls、negative_controls、check_source_consistency、align_audit、hash_consistency、_append_pitfall。远端连接脚本和历史一次性修补脚本不在本轮范围内；不要推断它们也已经可迁移。

## 检查与发布分开

`safe_pack_sync.py --verify-only` 保持只读。当前移交结构使用 `01_交付物/06_Skill` 作为 ZIP 与解包副本位置，开发活副本在 `02_活副本_Skill`。

由于开发副本已有修复而交付快照尚未同步，一致性检查可能失败，这是实际版本差异，不应修改判据掩盖。

旧 `--apply` 包含递归删除，已在写入前禁用并返回 2；不能用它同步交付物。以后需要同步时，应单独设计不批量删除的发布方式。本轮未执行打包或发布。
