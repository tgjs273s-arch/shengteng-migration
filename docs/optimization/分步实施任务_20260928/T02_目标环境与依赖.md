## 任务目标

给源码迁移提供确定的目标 API 和运行版本，避免混用历史机器信息。

## 必读输入

- T01 的模型/框架候选版本及待确认项。
- config/versions.lock、config/env_matrix.yaml、05_preflight.py、_envcompat.py、bringup.sh 和现有环境测试。

## 允许修改范围

- 环境说明、离线最小依赖清单及上述环境检查脚本中有证据的缺陷。
- 本步不更换硬件、不盲目升级共享环境，不更改模型算法或候选性能配置。

## 实施步骤

1. 分离 Windows 离线工具、Linux 编排、NPU 训练及推理依赖，确认 Python、CANN、驱动、torch/torch_npu、triton、transformers、MindSpeed/MM 的实际配对。
2. 将已测、历史记录、候选组合分别标注；固定一个近期支持目标，记录外部框架 commit 和补丁状态。
3. 为缺包、版本不配、NPU 不可用、Triton 回退提供明确检测结果和影响；不得由包能 import 推导 kernel 已在 NPU 生效。
4. 整理探测、安装、下载的不同副作用；复用现有 _envcompat，不再造独立环境管理框架。
5. 若进行获授权安装，保留前后版本和日志、采用明确隔离环境；不把旧锁中的安装命令直接当当前处置。
