## 实机步骤草案：每一条先核对 `--help` 和目标机路径

以下片段均以 `cd "$SKILL"` 为 cwd，以目标机 `"$PY"` 运行。路径变量为**上机前必填**，缺任一项则不执行。`RUN_ROOT` 为新建的本次独占目录；公共 `out/`、同一本账本、训练日志、NPU/端口不得并发使用。所有命令在执行前记录实际部署 commit、配置与资产 SHA-256；每步同时核对退出码、业务状态、必需产物及其本次身份。

1. **环境预检。** `"$PY" scripts/05_preflight.py --json --want full` 写公共 `out/preflight/capability.json`；`"$PY" scripts/00_probe_env.py --out "$RUN_ROOT/probe/env.json" --data-dir "$DATA_DIR"` 写 P0 档位。PRE/P0 会探测设备，可能执行 Triton NPU kernel；`--quick` 仅跳过该 kernel，不能作为实机数值结果。若能力缺件、版本或目标 checkout 不符，记录原始诊断后停止依赖链；不运行 `bringup.sh` 作为预检，因为它会安装/变更环境。
2. **迁移安装与来源。** 对目标机已核 bundle，`"$PY" scripts/22_migrate_qwen35.py apply --bundle "$BUNDLE" --out "$OVERLAY"` 生成 `migration_manifest.json` 与 converter overlay；`"$PY" scripts/22_migrate_qwen35.py install --bundle "$BUNDLE" --overlay "$OVERLAY" --target-checkout "$MSMM"` 安装到**专用**固定提交 checkout。`runtime` 子命令可在满足依赖且有完整本地 HF/processor 时执行，输出独立 `runtime_validation.json`。安装会改目标 checkout；运行前记录原 HEAD、工作树及允许的 diff，失败保存 stdout/stderr 和产物，不把静态安装当 NPU 通过。
3. **算子和模型验证。** `"$PY" scripts/30_verify_ops.py --out "$RUN_ROOT/verify" --env "$RUN_ROOT/probe/env.json" --migration-manifest "$OVERLAY/migration_manifest.json" --migration-bundle "$BUNDLE" --target-checkout "$MSMM"` 写 `ops_matrix.json` 和真实张量证据。即使退出 0，也逐行核对 `validation_level`、设备、错误及 contract-only；真实 CPU 小文本模型 prefill/decode/cache、NPU GDN/causal-conv 前向/梯度/末状态尚未运行。上游 decode 布局疑点须在真实类上复现后处理。text-only 冒烟不覆盖视觉路径或完整 0.8B。
4. **资产核验。** `"$PY" scripts/40_prepare_assets.py --env "$RUN_ROOT/probe/env.json" --out "$RUN_ROOT/assets" --model-dir "$MODEL_DIR" --data-dir "$DATA_DIR" --msmm-dir "$MSMM" --migration-bundle "$BUNDLE" --migration-overlay "$OVERLAY" --no-download` 写 `assets.json`；检查 `readiness`、`missing_required`、完整文件 hash、DCP metadata/payload、图片解码与数据顺序。`--no-download` 不补缺件；去掉它会下载大权重/COCO 并可能转换，须单独核对容量与资源授权。`--skip-coco` 与 `--skip-convert` 也不能把缺资产提升为就绪。
5. **配置和训练。** P1 `"$PY" scripts/10_analyze_points.py --out "$RUN_ROOT/analyze"`；P4 的 `DATA_DIR` 是数据总根，P2 的 `--data-dir` 应填从本次 P4 `assets.json` 核出的图片根 `COCO_DIR`（含 `train2017`；现有主入口关系为 `COCO_DIR=$DATA_DIR/coco`）。P2 对每次训练分别使用 `"$PY" scripts/20_plan_migration.py --env "$RUN_ROOT/probe/env.json" --points "$RUN_ROOT/analyze/migrate_points.json" --out "$RUN_ROOT/plan-<run>" --config-role reference --steps <5或100> --data-dir "$COCO_DIR" --data-json <真实训练JSON> --weight-hf <完整HF目录> --weight-dcp <已核初始DCP目录>`。逐次核对 `train_config.yaml`、`reference_config.yaml`、`config_manifest.json` 的角色、来源、几何及实际 `training.train_iters`。P5 使用 `"$PY" scripts/50_train.py --config "$RUN_ROOT/plan-<run>/train_config.yaml" --env "$RUN_ROOT/probe/env.json" --log "$RUN_ROOT/train-<run>/train.log" --workdir "$MSMM" --assets-json "$RUN_ROOT/assets/assets.json" --migration-bundle "$BUNDLE" --migration-overlay "$OVERLAY" --port <已预留端口>`。P5 `--steps` **仅提示**，不能改实际步数；`--log` 启动时会清空该文件，三次运行必须用不同路径。每次检查 `runs/p5-*/run.json`、`effective_config.yaml`、`train_integrity.json`、训练日志、实际保存目录及返回码，只有与本次配置吻合的 COMPLETE 才算完成该次训练。不能用 `--allow-gbs-mismatch` 宣称参考可比。
6. **精度与性能。** 对每次完整 100 步日志，`"$PY" scripts/95_extract_series.py --log <本次训练日志> --out <本次CSV> --summary-json <本次JSON> --expected-gbs <从有效配置核出的GBS>`；读取 `official_selection` 和独立 `window_selection`，保留原始全日志、rank、步序列及冷启动范围。P7 使用 `"$PY" scripts/70_judge.py --log <本次完整日志> --config <本次effective_config.yaml> --data-json <本次训练JSON> --baseline <最终登记的baseline YAML或兼容名> --baseline-log <已核原件对应日志> --config-manifest <本次P2清单> --assets-json <本次P4清单> --train-integrity <本次P5收据> --out <独占判定目录>`；T07 最终接口及 CLI 消费状态待交接复核。读取**本次** `judge_summary.json` 的 `execution_state`、`attempt_dir`、`numeric_validity`、`rule_status` 和 open gates；默认退出 0 只表示裁决产出，不能单看颜色或首步 loss。`--registry` 与 `--tag` 仅在计划追加独占账本时成对填写。
7. **导出、重载、推理与主入口。** T08 导出/重载 CLI、T09 真实推理 CLI、T10 四模式主入口的最终命令、输入和必需产物 **待各自 handoff 冻结后填写**。必须从本次 P5 checkpoint 导出，并验证完整 0.8B、MTP=0 的 DCP→HF logits roundtrip、模型/processor 真正重载及 NPU 实际推理；当前这些均未运行。推理保存媒体/提示/生成参数 hash、加载代码和设备、原始生成、解析与耗时；text-only 成功不代表视觉或工业场景评测成功。不得重新下载原模型来代替本次 checkpoint。
