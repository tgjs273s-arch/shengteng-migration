## 实际接口

- CLI：`python scripts/65_scene.py --model-artifact <T08 attempt/model_artifact.json> --model-dir <T08 export_hf> --processor-dir <同一 export_hf> --image <本地单图> --sop <UTF-8 文件> --device npu:0 --attention sdpa --max-new-tokens 160 --out <隔离目录>`。可显式 `--device cpu --cpu-diagnostic`；此分支永不标记真实 NPU 推理。旧位置图像和默认 `--out out/scene` 仍可解析；缺新产物/SOP 参数则留 `FAILED` 收据，位置图像与 `--image` 冲突返回用法错误 2。
- 每次创建独立 `attempt-*`，写 `inference_result.json`（`inference_result.v1`）。输入缺失/模型身份错/依赖错/设备错/生成错/保存错为 `FAILED`，生成 JSON 非契约为 `PARSE_FAILED`，解析为是/否时 `EXECUTED_PARSED`，合法“无法判断”时 `EVIDENCE_INSUFFICIENT`。后者要求 `bbox=null`、非空原因说明，不算业务正确。另存 `execution_state=NPU_EXECUTED|CPU_DIAGNOSTIC`、`real_inference_verified`、`business_validity=NOT_EVALUATED`。退出 0 仅为执行且合法解析，3 为前置/运行/解析失败，argparse 用法错误为 2。
- 原始生成先写 `generated_ids.json`（含完整及新增 token）和 `raw_generation.txt`，才尝试严格 JSON 解析并写 `parsed_result.json`。`compliant` 为“是/否/无法判断”；前两者要求图像内有限坐标，后者要求 `bbox=null`；`confidence` 在 [0,1]。解析失败仍保留真实原文，不打印或落盘旧 `EXPECTED` 答案。
- 身份：消费 T08 `model_artifact.v1` 的 `RELOAD_VERIFIED`、`reload_verified=true`、`post_export_identity_rechecked=true`、空 `problems`；实际扫描导出目录全部文件，比对清单逐文件 SHA/字节/集合；复算 `model_artifact_id`；核对 migration、P5 run 收据、所选 DCP 文件、P4/迁移清单引用、round-trip 输入及原始 logits SHA。模型和 processor 必须是同一导出本地目录。推理前后再核模型目录、manifest、媒体/SOP、模型源码哈希。
- 执行：通过 Transformers `AutoModelForImageTextToText`/`AutoProcessor` 重新加载导出 HF 权重，NPU 分支显式导入 `torch_npu`、固定实际卡号，检查缺/多/错参数、模型类、与 T08 对照的 HF 类、所有参数/缓冲和输入张量的设备类型及索引、实际 attention 配置；仅解码新增 token。记录框架、`torch_npu` 版本/导入失败、源码 SHA、实际设备集合、后端配置和 HF/目标框架边界。NPU 生成计时前后同步；加载和预处理字段是主机耗时，不报告无来源 TTFT。此流程不证明 MindSpeed-MM 训练 kernel 路径，也不证明工业判断正确。
