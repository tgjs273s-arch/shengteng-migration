先确定要迁移的输入源码、目标框架和验收参考，找回可能已经存在的真实适配，防止从占位目录误判成果或重复实现。

- 历史源码交付目录及归档证据目录；官方文件目录由用户提供，缺失时先用已核实仓库日志和清单，记录缺件。

## 实施步骤

1. 登记本轮 GPU 源码 revision/commit、模型规格、目标 MindSpeed-MM 版本；来源未落实时标记 SOURCE_PENDING，不把 refs 固定副本自动认定为官方唯一输入。
2. 核查本地与已有权限下的历史远端实现，逐项列出目标 modeling/注册代码、补丁、框架 commit、修改来源和对应日志。存在真实成果则归档其身份并提出纳入位置；未取得时明确缺口。禁止把配置和运行脚本作为模型实现。
3. 把官方 QA、PDF、模板和日志映射到四流程；标明原文要求、项目内部规则、待确认项。核对旧配置引用的精度帖子，未查到原文不照抄其权威结论。
4. 建立唯一基线 ID 与旧名映射建议，分开旧 officialA、Triton 和 AscendC 摘录；确认官方来源与本轮适用性是不同字段。
5. 记录官方日志 SHA-256 和当前源码版本；确认两个 baseline 副本是否仍一致；列出指定基线日志和配置应绑定的身份。
6. 给 T02–T09 冻结最低接口输入。无法获得远端源码或精度规则时，指出哪些迁移/验收环节受阻，同时允许不依赖它们的数学、日志和资产检查修复推进。
