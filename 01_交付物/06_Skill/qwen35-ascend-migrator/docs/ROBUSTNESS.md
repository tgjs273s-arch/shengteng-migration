# ROBUSTNESS.md —— 鲁棒性契约（可检验的不变量）

> **为什么需要这份文件**
> 2026-09-16 在一台**全新机器**上验证本 Skill，暴露 **20 个缺口**。逐个修完之后发现，
> 它们不是 20 个独立 bug，而是**同一类缺陷的 20 次显形**：
>
> | 缺陷类 | 实例 | 后果 |
> |---|---|---|
> | 隐含环境假设 | 硬编码 `apt` / `python3` / `/root/...` / `hostname` / `parents[3]` | 换机器就崩（坑 30/37/38/39） |
> | **判据条件恒真** | `"VERIFY_OK" in out or rc==0`、`len([])<=1`、`checks=[]→fails=0` | **看起来通过，什么都没证明**（坑 33/42/47） |
> | **消费陈旧产物** | `tests/tmp/` 带着开发机 13 天前的产物被打包 | **假阳性**（坑 35） |
> | **判据自身写错** | `triton.program_id` 不存在 → 假阴性 | **主动降级，白扔 51× 性能**（坑 46） |
> | 静默降级 | 步骤跳过但不登记 | 交付物里出现"未声明的可比性" |
> | 中断不可续 | 19GB 下载失败即前功尽弃 | 时间成本（坑 10/29） |
>
> 所以"更好的鲁棒性"不是"多加断言"，而是**把上述六类缺陷结构性堵死**。
> 本文件就是这六条的结构化承诺 —— 每一项都**可被机器验证**，不是口号。

---

## 一、七条不变量（INV-1 … INV-7）

### INV-1 · 无隐含环境假设
**任何**环境相关取值必须经 `scripts/_envcompat.py` 取得，不得散落在脚本里。

| 维度 | 抽象入口 | 曾经的坑 |
|---|---|---|
| 解释器 | `python_exe()`（`PYBIN` 优先，绝不假定 `python3`） | 坑 38：`python3` 与 `pip3` 是两个解释器 |
| 包管理器 | `pkg_manager()` / `install_hint()`（dnf/yum/apt 分派） | 坑 37：openEuler 无 apt |
| 路径 | `skill_root()` / `pkg_root()` / `find_repo_root()`（向上找标记目录） | 坑 30/36：`parents[N]` 硬编码深度 |
| 主机名 | `safe_hostname()`（读 `/proc`） | 坑 39：极简镜像无 `hostname` |
| 版本 | `norm_ver()`（剥 `+cpu`）、`ver_tuple()`、`is_prerelease()` | 坑 50：`2.7.1+cpu` 被判 drift |
| CANN | `cann_version()`（多路径 + `readlink`） | 坑 40：版本文件名不固定 |
| SoC | `torch_npu_info()`（`npu-smi` 只给通用名） | 坑 8：`Ascend910` vs `Ascend910_9382` |

**验证**：`python3 scripts/_envcompat.py --selftest` → `SELFCHECK_OK`
**验证**：`90_selfcheck_gates.py` 的静态守卫（8 条模式，含去注释/窗口/文件级放行）

### INV-2 · 判据必须可证伪（★ 本契约的核心）
**每一个关键判据都必须被证明"喂坏输入时会失败"。**

不是"加断言"，是**测试断言本身**：`scripts/90_selfcheck_gates.py` 对每个判据做双向验证：
```
good 输入 → 必须通过
bad  输入 → 必须失败      ← 若 bad 也通过，判为 GATE_VACUOUS（该判据是装饰）
```
当前覆盖 8 项动态对照（资产完整性 / 账本篡改 / 重复 tag / 判定确定性**与证据敏感性** /
非法输入 / 红线 verdict_id 重放 / 环境模式逻辑 / 模式差异）。
其中 `judge_determinism` 额外验证**敏感性**：改一个字节，`verdict_id` 必须变 ——
否则"纯函数契约"只是空话。

**★ 6 次同族教训（必须内化为纪律）**：判据反复因**依赖未确认的格式假设**而失效：

| 次数 | 依赖了什么 | 后果 |
|---|---|---|
| 坑 42 | `"VERIFY_OK"` 恒存在 → `or` 恒真 | 判据永远通过 |
| 坑 56 | 取 `stdout+stderr` 的**最后一行** | 取到 Warning → 误判 triton 不可用 |
| 坑 60 | `tl` 在函数内 → JIT 命名空间找不到 | 假阴性 → 主动降级丢性能 |
| 坑 62 | **缩进**当作作用域 | 自检产生 7 条假阳性 |
| 坑 84 | **枚举**已知异常类型 | 真实异常 `PackageNotFoundError` 漏掉 |
| 坑 88 | **行首锚定**（`^Xxx`） | torchrun 的 `[rank0]:` 前缀让提取器全失效 |

> **纪律**：面向外部文本（日志/命令输出）的判据，
> **不得假设行首 / 行序 / 编码 / 输出位置**；一律用「**容忍前缀 + 语义标记 grep**」，
> 并且匹配模式必须能**同时命中带前缀与不带前缀**的样本（双向自检）。

**验证**：`python3 scripts/90_selfcheck_gates.py` → `GATES_OK`
**注意**：SKIP 不算失败但也**不算通过**，会显式打印（否则就是坑 34 的翻版）。

#### INV-2 推论 · 同源原则（坑 110/111 后升格为硬纪律）

> **跳过条件、验收条件、运行条件、闭环收敛条件，必须来自同一个事实源，
> 并且等于"真正需要成立的那件事"。**

这条不是新口号 —— 坑 110/111 正是它的**直接违反**，而且违反的方式极具欺骗性：
**每个环节单独看都"有依据、有检查"，只是检查的不是同一件事。**

| 违反形态 | 实例 | 后果 | 代码级防线 |
|---|---|---|---|
| 运行条件与验收条件不同源 | 运行 world=2（日志实测），验收 world=1（`70_judge.py` 硬编码） | 任何多卡运行恒判 `NOT_COMPARABLE`，伪装成"精度不达标" | `70_judge.py` 同源解析 + `WORLD_CONFLICT` 拒判 + `--selftest` 8 用例 |
| 运行条件读原文、验收条件读解析 | `50_train.py` 用正则扫文本算 GBS；配置 YAML 已损坏也照样"通过" | 红线检查假通过，几分钟后才在训练器里炸 | GBS 自检改为解析 YAML；解析失败**启动前拒执行** |
| 产物未验证就落盘供下游消费 | `20_plan_migration.py` 先写文件再校验，回读不一致只算 `warnings` | 坏配置静静躺在磁盘上被 P5 消费 | **先校验后落盘**；回读不一致 = 致命 `rc=3` |
| 把"未知"写成默认值 | "我不知道 world" → 写成 `1` | 未知被伪装成已知，下游产出"看起来正常"的结果 | 无法确定时**拒判**，并说明如何补全 |
| **只核对派生量、不核对关键量** | 陈旧配置 `dp=1/mbs=2/gas=4` 与运行态 `dp=2/mbs=4/gas=1`，**GBS 都是 8** | 红线（GBS=8）两边都通过，判定却读到错的 `dp` → 被误读成"配置偏离官方几何" | 判定链**以日志运行态为主源** + `STALE_CONFIG` 告警 + **逐项比对 dp 本身**（坑 114） |
| **修一条路径就以为缺陷绕过（对称路径未查）** | `load_rank0_and_broadcast` 只覆盖 **load**；**save** 仍走 DCP plan 广播（HCCL 不支持 gather） | 载入正常、训练正常，**100 步跑完才在收尾保存处 SIGABRT**（rc≠0） | 诊断规则补专属分支 + `save_format: hf`（或 `save: null`）规避；**验收坚持 rc=0**（坑 113） |

> **纪律**：同一事实存在多个来源时（配置声明 / 日志实测 / 显式传参），
> **必须在代码里交叉核对，不一致即拒判** —— 不许由人或脚本各自挑一个"更权威的"。
> 另外：判据报红时，**先怀疑判据本身**（与坑 46/107 同族：判据也是需要被验证的组件）。

### INV-3 · 绝不消费来路不明的产物，也绝不破坏已有证据
判据只允许消费**本次运行产出**的文件；任何同步/推送操作必须**默认保守**。

- `sk04_judge` 自检开跑前清空 `tests/tmp/*.json` 并打印清空数量（坑 35）
- `pack_skill.py` 打包前同样清空（否则把开发机产物发出去）
- `run_from_zero.sh --resume` 只在"产物存在**且比它的每个输入都新**"时跳过，
  并在报告里记为 **`RESUMED`（不是 PASS）**——让读者能区分"真跑了"和"复用了"
- ★ **推送/同步必须合并而非替换**（坑 67）：`ssh_tool.push_dir` 曾用 `rm -rf + mv` 整体替换，
  把远端积累的 `out/`（训练日志、下载产物、裁决表）一并抹掉。
  现改为**覆盖式合并**（`cp -a` 逐文件覆盖，保留远端独有文件），整体替换需显式 `--clean`。
  **"代码可以重推，跑了几小时的证据不能重来。"**
- ★ **幂等的跳过条件必须与验收条件同源**（坑 70）：曾出现"空目录被当作已存在 →
  永久跳过下载 → 权重一直是 0"的死锁。现由 `_weights_ready()` 等实质判定统一两者。

**验证**：`run_from_zero.sh` 报告含"复用已有产物 N"列；`pack_skill.py` 打印清理条数；
推送后远端 `out/` 内容仍在。

### INV-4 · 降级必留痕，账本不许空
任何"因环境不支持而换路径"必须调用 `_envcompat.degrade()`，写入 `out/degradations.json`。

- `05_preflight.py` 开工前导出**能力矩阵**（OK / DEGRADED / BLOCKED / SKIP）并登记降级
- `run_from_zero.sh` 结束时做**账本一致性检查**：任一阶段日志出现 `DEGRADED` 而账本为空
  → 判为失败（`LEDGER_INCONSISTENT`）
- 能力矩阵里显式写出"**因此不得宣称什么**"（如数据非全量同源 → `pointwise_claim_allowed=BLOCKED`）

**验证**：`run_from_zero.sh` 报告含"★ 降级登记"章节；预检输出含影响说明。

### INV-5 · 失败即响亮，SKIP 不等于 PASS，也不等于 FAIL
三态语义被严格区分并**全部显式输出**：

| 状态 | 含义 | 是否算失败 |
|---|---|---|
| PASS | 确实验证通过 | 否 |
| FAIL | 确实验证失败 | 是 |
| SKIP | **因缺输入/平台限制未验证** | **否，但必须打印**（既不静默当通过，也不冒充失败） |
| RESUMED | 复用已有产物，本次未执行 | 否，但报告里单列 |

历史上这三点都错过：SKIP 被计为失败（坑 34，淹没信号）、SKIP 被静默当通过（坑 33，造假）。

**验证**：`90_selfcheck_gates.py` 汇总行同时输出 PASS/SKIP/FAIL 计数。

### INV-6 · 长任务可中断、可续跑、可重试
| 场景 | 机制 |
|---|---|
| SSH 通道（token 5 分钟有效） | 一律 `setsid nohup ... </dev/null >log 2>&1 &`；**三 fd 全重定向**（坑 44：tee 持有写端导致挂死） |
| 下载（19GB COCO / 229MB llava） | `_envcompat.download()`：`curl -C -` **断点续传** + `Content-Length` **大小校验** + 退避重试 |
| 源站限流（HTTP 429） | `pip_install()` 指数退避 + 多源回退；`SOURCES` 每类**至少两源** |
| 逐阶段续跑 | `run_from_zero.sh --from <阶段>`；`--resume` 走陈旧性校验 |
| 单命令 120s 被掐 | 长任务后台化 + 日志轮询，绝不前台长跑 |

**验证**：`SOURCES` 每类 ≥2 源自检；`download()` 校验 `expected==bytes` 才返回 ok。

### INV-7 · 自检本身是四层，且每层都能独立失败
```
L1 结构完整性 + .py 语法 + **.sh 语法（bash -n）** + 配置可解析
L2 判定链可用性（SK04，含包内示例重放 → 0-GPU 自证红线 verdict_id）
L3 环境一致性（acceptance 严格 / portability 报告 drift，两者都跑）
L4 判据负向对照（INV-2）
```
`L1` 此前**只检查 .py，从不检查 .sh**（坑 52）——而 bash 脚本是流程入口。
`_find_bash()` 还会**实跑 `bash -c 'echo BASH_OK'` 验证可用性**：
`which bash` 在 Windows 上会命中坏的 WSL 转发器（坑 53）。**"找得到"≠"能用"。**

**验证**：`python3 selfcheck.py` → `SELFCHECK_OK`（四层）

## 二、抽象掉的东西（换机器时不用改代码的清单）

| 类别 | 已抽象 | 仍需实测确认 |
|---|---|---|
| 芯片 | 靠"HBM ≥60GB 且 die ≥2"匹配配置档，不靠型号名 | 新 SoC 的**性能画像**（配置档是几何正确的，速度需实测） |
| 发行版 | 包管理器分派、`/proc` 读主机名 | 极端裁剪镜像可能缺更多命令（已内建"命令缺失清单"探测） |
| Python | 锁定单一 `PYBIN`、保障 `Python.h` | **新 Python 版本下 triton 与 CANN 的配对**（须实测，不可按版本号盲判） |
| CANN | 多路径读版本、识别预发布版 | β/RC 版的 torch_npu 配套 |
| triton | **实测优先**：能用就用（记录实际版本），不通才装 3.2.2 复测 | 具体三元组 |
| 数据 | 字节/样本数锚点 + 多源 + 续传 | 官方源本身的可用性 |

**未覆盖（诚实声明）**：
- 非昇腾平台（如 GPU）的迁移路径未实现，只有 `cpu_only` 静态轨
- 极端网络环境（完全隔离）下 P4 需人工搬运，脚本会 `BLOCKED` 而非伪造
- 多机多卡（`nnodes>1`）未验证
- **新硬件上的数值一致性**：`step1 loss == 1.924621` 只在旧机器（9382 + CANN 9.1.0 GA）坐实；
  新机器（9382 + CANN 9.1.0-beta.3）**待实测**，两种结果都要如实报告

## 三、失败模式 → 防线 对照表（本契约的索引）

| 失败模式 | 防线 | 守卫/判据 |
|---|---|---|
| 判据恒真 | INV-2 负向对照 | `90_selfcheck_gates.py`（VACUOUS 检测） |
| 消费陈旧产物 | INV-3 | `selfcheck_sk04` 清 tmp + `--resume` 陈旧性校验 |
| 硬编码路径/命令/解释器 | INV-1 | `_envcompat` + 8 条静态守卫 |
| 静默降级 | INV-4 | 能力矩阵 + 账本一致性检查 |
| SKIP 被误计/被静默 | INV-5 | 三态显式输出 |
| 判据自身写错（假阴性） | INV-2 静态守卫 | 坑 46 回归守卫（`triton.program_id`） |
| 后台任务挂死 | INV-6 | `</dev/null` + 三 fd 重定向 + TTY 守卫 |
| 大文件下载前功尽弃 | INV-6 | 断点续传 + 大小校验 + 多源 |
| .sh 语法错未被发现 | INV-7 | `bash -n` 闸门 + `_find_bash()` 可用性验证 |
| 编码导致自检崩溃 | INV-7 | 所有 subprocess 显式 `encoding="utf-8", errors="replace"` |
| **判定器自身恒红**（判据 bug 伪装成结果不合格） | INV-2 同源原则 | `70_judge.py --selftest`（8 用例）+ `WORLD_CONFLICT`/`WORLD_UNKNOWN` 拒判 |
| **运行条件 ↔ 验收条件不同源** | INV-2 同源原则 | P5 断言"配置 dp ≠ 本次 world → 拒绝启动" |
| **未验证的产物被落盘消费** | INV-3 + INV-2 同源原则 | P2 先校验后落盘；回读不一致 = 致命 |
| **环境相关的开关靠人记得开** | INV-1 + INV-4 | P0 按探测到的 CANN 标识决定 `load_rank0_and_broadcast`，判据随档位落盘 |

## 四、怎么用（三条命令）

```bash
python3 scripts/_envcompat.py --selftest      # 兼容层自身
python3 scripts/05_preflight.py --json        # 开工前：能力矩阵 + 降级登记
python3 selfcheck.py                          # 交付前：四层自检（含判据可证伪）
bash    scripts/run_from_zero.sh --quick      # 端到端（--full 为全量）
```

**判读**：
- `SELFCHECK_OK` + `GATES_OK` + `PREFLIGHT_OK` → 可以开工/可以交
- 出现 `VACUOUS` / `GUARD_BROKEN` / `LEDGER_INCONSISTENT` → **判据体系有问题，先修判据再谈结果**
- 出现 `SKIP` → 看原因：是平台限制（目标机上会跑到）还是缺输入（该补就补）
