# 推荐配置 A / 保底配置 B —— 决策记录

> 结论一句话：**A 作推荐、B 作保底**（用户 2026-09-21 决定）。
> **出货口径的量化结论：A 比 B 快 24.4%（95% 区间 [22.41, 26.37]，以 A 为基准的配对差；
> 等价说法：A 少用 19.6% 的时间），代价是设备显存峰值 +21.8%（19786 → 24091 MB）。**
> 该结论来自第 2 节"已实测 ③"（出货配置的直接对比，2026-09-21 15:39 完成）。
> 引用时必须连同**显存**与**口径**（以谁为基准）一起给出；`official_comparable=false`（mock 数据），

## 1. 两份配置是什么

| | A（推荐） | B（保底） |
|---|---|---|
| 文件 | `config/templates/qwen3_5_0_8B_recommended_A.yaml` | `config/templates/qwen3_5_0_8B_fallback_B.yaml` |
| 来源 | **真机 A/B 里 B 臂用的那份，逐字节照搬**（实测源 sha256 前 12 位 `4e5f978599da`，与链路日志 `AM_BASE_AB_SHA256=4e5f978599da93a7` 一致） | 实测的官方开关组那份，**只改一个键**：`model.skip_gdn_recompute` → `True`（官方值） |
| `features.recompute` / `enable_chunk_loss` / `enable_activation_offload` | **False / False / False** | True / True / True |
| `model.skip_flash_attn_recompute` | **False** | True |
| `parallel.fsdp_plan.pregather` | **True** | False |
| `parallel.fsdp_plan.reshard_after_forward` | **False** | True |
| `model.skip_gdn_recompute` | **False** | True（官方） |
| 工作负载（两者相同） | 官方几何 dp2/mbs4/gas1、GBS=8、1 图每样本、1024 样本、100 步 | 同左 |

A 是"**用显存换速度**"的工作点：关掉官方那五条省显存开关、打开 pregather，代价是每步激活全留。
B 是"全官方值"的工作点。

两份模板由脚本生成（可复现）：`交付物生成脚本/make_profile_templates.py --evidence <证据目录> --templates <Skill/config/templates>`。
脚本会把 A↔B 的**实际差异**与声明的 **7 个键**逐键对照，并复查 `GBS = mbs × gas × world = 8` 红线；不满足即拒绝落盘。

### **已实测 ③：A 直接对 B（出货对比，7 键差异）** —— 2026-09-21 15:39 完成
`/root/ops/AB_AVSB_20260921/`（3 对平衡顺序 `A,B,B,A,A,B`，100 步；`--declare` 7 键，实际差异逐键相符）

| 组 | 窗口步时长（每一次） | 均值 | 设备显存峰值 `max_allocated` |
|---|---|---|---|
| **A 推荐** | 418.6 / 418.0 / 420.5 ms | **419.0 ms** | **24090.6 MB** |
| **B 保底** | 521.45 / 522.85 / 519.4 ms | 521.2 ms | 19786.3 MB |

```
配对差 mean = +24.391%（口径：以 A 为基准，(B−A)/A）  95% 区间 [22.411, 26.372]，不含 0
等价说法：B 用时是 A 的 1.244 倍 ⇒ **A 少用 19.6% 的时间**
A 臂自身漂移 = 0.6%（比 ① 的 5.518% 干净得多，是本轮区间更窄的原因）
数值判据：step1 双方完全一致（0.1154926）；loss 逐点最大差 0.0%，grad_norm 0.0465%（前 2 步）
```

⇒ **出货口径的结论**：**A 比 B 快 24.4%（95% 区间 [22.41, 26.37]，A 为基准的配对差），
代价是设备显存峰值高 21.8%（19786 → 24091 MB）**。两个轴必须一起报。

**口径提醒（否则会读反）**：框架的判定词是 `NO_GAIN`，它的语义是"**B 相对 A 没收益**"——
本实验里 **A 才是推荐配置**，所以要看的是"B 显著更慢"，数字本身没有问题。
引用时**必须写明以谁为基准**：以 A 为基准是 **+24.39%**（快），换算成"省时比例"则是 **19.6%**。

**三项实验的相互印证（同一配置跨轮次吻合度）**

| 配置 | ① 轮 | ③ 轮 | 差 |
|---|---|---|---|
| 我方开关组 + `false` | 441.6 ms（① 的 B 臂） | 419.0 ms（③ 的 A 臂） | 5.4% |
| 官方开关组 + `true` | 524.9 ms（② 的 A 臂） | 521.2 ms（③ 的 B 臂） | 0.7% |

⇒ **同一配置跨轮次有约 5% 的自然散布**（两台轮次之间可能有系统性偏置，例如机器状态）。
这正是**只引用配对差、不引用单臂绝对值**的原因：③ 的两臂在同一轮里一起偏移，配对差仍然成立。

**关于"能不能相加"**：① 的 19.07%（6 键开关组，两臂 `skip_gdn` 同为 false）与 ② 的 −7.18%
（`skip_gdn` 单项，基线是官方开关组，且 UNCERTAIN）**基线不同、交互项未知**，本来不可相加；
现在 ③ 直接量了 7 键差异 ⇒ **以 ③ 的 24.39% 为准**，① 与 ② 只作机制分解（哪部分贡献多少）。

## 4. 选择 A 的代价与边界（必须随交付一起出现）

1. **A 相对官方有 7 处配置偏离**，已逐条登记在 `config/versions.lock` 的偏离清单
   （`deviation.config.fsdp_plan` / `features` / `skip_flash_attn_recompute` / `skip_gdn_recompute`）。
   "登记"表示**我们知道它不同且量过代价**，不表示它比官方"更正确"。
2. **`official_comparable = false`**：本机是 mock 数据 ⇒ 上述所有数字**只能与同机、同数据、
   同几何的对照臂比**，**不得**与官方窗口中位数 431.3 ms 做比值。
3. **显存门槛**：A 的峰值约 24.1 GB/进程分配口径。若评委机器的可用显存显著小于本机
   （单 die 64 GB），A 可能跑不动 ⇒ **B 就是为这种情况准备的**（峰值约 19.8 GB，全官方值）。
4. **B 的定位**：不是"更差的兜底"，而是"**可复现优先**"的配置——全官方值、显存更低；
   代价是慢（相对 A 的开关组约 19%，但注意第 2 节说明：A 对 B 的直接数字**待测**）。
5. 数字的**口径**：窗口 = 第 11..100 步的步时长中位数；统计单位是"一次运行"；
   3 对配对 ⇒ t(0.975, df=2) = 4.303（区间偏宽，已在第 2 节如实给出）。
