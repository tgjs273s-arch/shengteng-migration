### 8.2 可以写、不可以写

**可以写**：

> 在当前已测试环境、mock 数据与该配置下，**同配置重复未满足完整窗口（1..100）的逐点 2% 一致性要求**；

> `use_deter_comp=true` 门控消除。原因仍在定位，**尚未归因于平台，也不据此推断官方基线不可复现**。

### 8.3 边界（本方法的可见范围）

- `grad_norm` 只打印 **3 位小数**、`loss` 8 位有效 ⇒ **精度以下的差异本方法看不见**；
  "第 1 步 loss 相同"**不等于**"第 1 步计算逐位一致"。
- 落盘权重为 **bf16** ⇒ "逐位相同（153 个张量）"只在该存储精度下成立。
- 权重差异是 **100 步累积结果**，不能单独把责任落到第 1 步；它与②是**两条独立证据**，方向一致。
- ✅ **正对照已补（2026-09-22）**：重跑 2 次 `use_deter_comp=true`（100 步、保留 checkpoint）⇒ 落盘权重 **473/473 逐位相同**（`CKPT_IDENTICAL`），而 `false` 侧为 320/473 不同 ⇒ **方法灵敏度已证明**，且该非确定性被该开关完整门控。
  "确定性路径下权重应逐位相同"这一条**尚无实测正对照**，需重跑。

  ⇒ **没有任何一臂优于基线**；此前一轮报的"预取 4 省 3.91%"**未复现**。
- ★ **噪声底噪 ≈2%**：同机同会话、同配置的两批基线中位步时长为 731.6 ms 与 716.5 ms。
  ⇒ 任何小于**噪声 2 倍**的效应一律先按 UNCERTAIN 处理；要报小效应必须增加重复数并给区间。
  **这也正是"≥5%"门槛的必要性来源。**
- ★ **代码级同步候选已排除（2026-09-22 补：归因 + 端到端 A/B 双证据）**：`clip_grad=0.0` 时仍每步调用的
  `clip_grad_norm`（→ `LpNormV2`，320 次/步）与每步 loss 的
  `average_losses_across_data_parallel_group`（→ hccl `allReduce`，8 次/步）。
  **① 归因**：两者 kernel 时间合计仅 **0.87%**（0.45% + 0.42%；`--with-stack` profile 的 35750 行 kernel 明细 / 5 步）。
  **② 端到端 A/B**（3 臂 × 3 轮拉丁方、同批次；N 臂 3 轮底噪 **1.53%**、阈值 = `max(2×1.53, 5) = 5.0%`）。
  口径统一为 `savings_pct = (基线 − 候选) / 基线 × 100`（**正 = 候选更快**）：
  **C1（跳过 grad-norm）= +1.7645%**，95% 区间 **[−4.4405, +7.9695]**（n=3）；
  **C2（跳过 loss all_reduce）= +0.0194%**，区间 **[−1.8965, +1.9353]**。
  两者均判 **`PERFORMANCE_NOT_MET` / `CI_LOWER_BELOW_THRESHOLD`**（退出码 4）。
  注入有正对照（C1 三轮 `grad_norm` 全打印 0.0，N/C2 为 ~34.17）。
  ★ **本组数字与外部复核的独立复算逐位一致**。
  ★★ **表述边界（更正）**：C1 区间上界 **7.97% > 5%** ⇒ 本实验**既不能确认达标、也不能证伪**
  ⇒ **不得**写「数学上已证明达不到 5%」。停止投入的理由是：**① 证据不足（区间跨零、n=3）；
  ② 点估计小（1.76%）；③ 代价大于收益**（见下）。
  归因给出的 **0.87%** 是**算子时间占比**，**不是**端到端省时的置信上界。
  **且代价大于收益**：跳过 grad-norm 会打断观测指纹（`sk04_judge` 的 `fingerprint_observed.py`
  要求 `grad norm:` 并把它写进指纹），并使 `scripts/59_config_ab.py` 的 `PAT`
  **一行都解析不出来**（连性能测量本身都失效）；跳过 loss all_reduce 会把打印的 loss
  从"DP 平均"换成"本地 rank 值"，**改变整条 loss 数值链的语义**。
  详见 [优化候选评估固定流程](优化候选评估固定流程_20260922.md) §5 与
  `protocols/codelevel_sync_candidates_20260922.json`（框架**已还原、逐字节核对**；卡时 ≈0.39）。
  ⇒ **优化方向改为算子族**：GDN/linear-attn 28.2%、MatMul 20.5%、小算子/拷贝/cast 簇 16.3%（≈4000 次发射/步）。

### 9.5 新增的流程规则（已落进工具与协议）
