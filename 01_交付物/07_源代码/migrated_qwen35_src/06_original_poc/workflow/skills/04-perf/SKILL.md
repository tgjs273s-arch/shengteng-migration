# 技能 04：性能优化循环（T7）

## 循环七步（每轮严格执行）

```
① 基线：msprofiler 采集当前版本 → Top算子耗时榜 → logs/baseline_<轮次>.json
② 假设：提出一个优化方向（算子融合/访存优化/批处理/精度模式），说明依据
③ 修改：只改这一个变量（禁止一轮多改）
④ 守门：verify/compare.py 必须仍通过（精度不劣化是硬约束，不通过则回滚）
⑤ 基准：重跑性能测试，记录 首token延迟 / 端到端延迟 / 吞吐(tokens/s)
⑥ 记录：结果写一行进 docs/perf_table.md（含轮次/假设/改动/前后数据/结论）
⑦ 决策：改善 → 保留进下一轮；无改善或劣化 → 回滚，换新假设
```

## msprofiler 使用要点

```bash
# 采集（示例，具体参数以昇腾官方文档为准【待核实-昇腾】）
msprof --application="python infer.py" --output=./prof_out
msprof --export=on --output=./prof_out
```
- 分析关注：Top 算子耗时占比、AI Core 利用率、内存拷贝占比；
- 解读结论必须基于采集数据，不许凭印象说"应该是XX瓶颈"。

## 优化方向优先级（本项目判断）

1. **GDN 算子**（自研实现，优化空间最大）：Triton kernel 化、tiling 参数调优；
2. 注意力与视觉塔：参照昇腾融合算子库【先探测】；
3. 批处理与输入流水线：图像预处理异步化；
4. 精度模式：评估 bf16 对精度与速度的影响（需任务层验证配合）。

## 产物

- `docs/perf_table.md`：累积对比表（= 复赛《性能测试报告》主体数据）
- `logs/perf_<轮次>_<时间戳>.log`：每轮完整日志
- 优化前后 msprofiler 报告截图/导出（答辩证据）

## 纪律

- 每轮必须有"改前数据"才能声称"改善"；
- 性能结论只认 NPU 实测，禁止用 CPU 数据外推；
- 连续 3 轮无改善 → 停止该方向，回到 Top 算子榜重新选目标。
