# Qwen3.5 昇腾迁移 POC（qwen3_5-migrate-poc）

> 本仓库是 **初赛 POC**，目标是用**最小可运行证据**证明一条完整闭环：
> **识别迁移点 → 算子在昇腾语义下算通 → 落到真实工业场景**。
> 不追求在本地把大模型端到端跑满，而追求**每一环都有可截图的真证据**，并把"必须在实卡上才能完成的部分"诚实标注出来。

运行环境：`conda` 环境 `d2l`，CPU 推理（无 NPU 实卡），PyTorch 2.2.2。

主线模型：**Qwen3.5-0.8B**（原生多模态：Gated DeltaNet 线性注意力 + 视觉 3D-Conv，
既能看图、又能建模动作时序，契合环3"看画面判操作手法"的语义+时序推理需求）。

---

## 一、三环证据链（总览）

| 环 | 脚本 | 证明的事 | 本地证据强度 |
|---|---|---|---|
| **环1 · 识别** | `poc1_*.py` | 真解析出模型中需要迁移/适配的节点 | ✅ 实算 |
| **环2 · 计算** | `poc2_*.py` | 关键算子 forward 跑通、张量 shape 全程贯通 | ✅ 实算 |
| **环3 · 场景** | `poc3_scene.py` | 工业**操作规范/工艺手法**判定的推理链路与输出格式定义；并实测迁移目标类与端到端真跑的依赖门槛 | ✅ 设计 + 依赖实测 |

> 三环串起来回答评委的三个问题：**迁什么（环1）→ 迁得对不对（环2）→ 迁了用在哪（环3）**。

## 二、各环说明与对应截图

### 环1 · 识别迁移点 —— `poc1`
- **做了什么**：解析目标模型结构，定位需要迁移/替换的算子或子图节点。
- **截图证据**：`snapshots/poc1_*.png`，输出中**真实列出**了识别到的迁移节点（非模板）。
- **结论**：迁移范围被**程序化**界定，而非人工拍脑袋。

### 环2 · 算子算通 —— `poc2`
- **做了什么**：对环1识别出的关键算子，构造输入张量做 `forward`，验证在目标后端语义下计算可执行、输出 shape 与预期一致。
- **截图证据**：`snapshots/poc2_*.png`，打印出贯通的 shape / 计算结果（非模板）。
- **结论**：迁移不是"改个名字"，而是**算得通、对得上**。

### 环3 · 场景落地 —— `poc3_scene.py`
- **场景**：工业**操作规范 / 工艺手法**判定——看画面判断操作手法是否符合 SOP
  （如法兰螺栓紧固是否走对角交叉顺序、是否单边连续拧紧），输出结构化判定 JSON。
  该场景需**语义 + 时序 + 常识推理**，要看动作过程，正对应原生多模态视觉侧
  **3D-Conv 看动作过程**的能力，是大模型的不可替代之处。
- **调用对象**：迁移**目标类** `Qwen3_5ForConditionalGeneration`，目标权重 `Qwen/Qwen3.5-0.8B`，
  输入图 `samples/factory.jpg`。
- **预期输出格式**（场景推理链路定义，与脚本实跑打印逐字一致）：
  ```json
  {"compliant":"否","step":"法兰螺栓紧固","issue":"未采用对角交叉顺序，单边连续拧紧，易致密封面受力不均","evidence":"操作者沿圆周同向连续拧紧第3、4颗螺栓","bbox":[286,210,452,372],"confidence":0.88}

  ```
- **本地实测的降级表现（脚本真实打印，非崩溃）**：
  - `[transformers] Disabling PyTorch because PyTorch >= 2.4 is required but found 2.2.2`
  - `[降级] 迁移目标类不可用：ImportError: cannot import name 'AutoProcessor' from 'transformers.models.qwen3_5'`
    ——即 `qwen3_5` 包骨架已建、但 `AutoProcessor` / 目标类导出尚未补全；
  - 脚本随即打印说明：「此为设计内降级，非崩溃。迁移落地（modeling_qwen3_5.py + NPU kernel 就位）后，本脚本无需改代码即真跑。」
- **与环1 的交叉印证**：上述 `ImportError` 与环1 **静态扫描**所指出的迁移缺口**指向同一点**
  （一静一动，交叉验证），证明本 POC 对"迁到哪、差什么"做了双重确认。
- **端到端真跑的依赖门槛（本地实测得出）**：
  - 迁移目标类导出补全（`modeling_qwen3_5.py` + 对应 NPU kernel 就位，**首要**）；
  - 需 `transformers`，且其要求 **PyTorch ≥ 2.4**（本环境为 2.2.2，故 transformers 禁用 torch、模型类不可用）；
  - 需 `qwen_vl_utils` 视觉预处理包；
  - 需下载 `Qwen/Qwen3.5-0.8B` 权重（数 GB），并依赖**实卡算力**做合理时延推理。
- **截图证据**：
  - `snapshots/poc3_scene.png` —— 场景链路、降级实测与预期输出格式（即上图）；
  - `snapshots/poc3_deps.png` —— 端到端真跑的依赖实测记录。
- **结论**：目标场景 =「看画面判操作手法是否符合 SOP」，需语义+时序+常识推理，
  正是原生多模态（视觉 3D-Conv 看动作过程）的不可替代之处；
  场景**链路设计完整、输出契约明确**，复赛将迁移后 Qwen3.5-0.8B 接入此处即闭环。

## 三、诚实声明（Engineering Honesty）

1. 环1、环2 为**本地实算**证据；环3 为**链路设计 + 迁移目标类/依赖实测**证据。
2. **环3 本地不真跑的根本原因，是迁移目标类尚未就位**——而这正是本 POC 的题中之义：
   POC 证明的是**迁移缺口与可迁移性**，而非"迁移已全部完成"。即便升级 PyTorch 至 ≥2.4，
   只要 `qwen3_5` 的类导出未补全，环3 仍会降级；故**降级是设计内行为，非缺陷、非借口**。
   PyTorch 版本、权重下载、实卡算力是叠加其上的**部署期门槛**。
3. 环3 端到端真推理 = 迁移落地 + 昇腾实卡 + 对应 CANN/驱动 + 权重下载，属**部署阶段**工作，本 POC 以"同一脚本上卡即跑"的方式交付接口，不在此伪造本地结果。

## 四、复现

```powershell
conda activate d2l
python poc1_*.py     # 环1：识别迁移点
python poc2_*.py     # 环2：算子算通
python poc3_scene.py # 环3：场景链路 / 迁移目标类与依赖实测

```

> 环3 在缺少 `samples/factory.jpg` 时输出预期格式；放入样例图后先尝试真跑，
> 迁移目标类/依赖任一不就位即**优雅降级**（设计内，非崩溃），并打印预期输出契约。
