# 作品说明文档（复赛）

## 一、创意描述

**一句话创新点**：我们交付的不是"改好的模型"，而是**"会改模型的流程"**——
一套面向昇腾算力的**自动迁移 Skill**：输入模型源码与目标环境，自动完成迁移点识别、
迁移方案生成、算子验证、数据与权重准备、训练执行、性能基准与精度判定，
把大模型向国产算力迁移从"专家逐行读源码的手工活"变成**可复用、可复现、证据可溯源**的自动化流水线。

**成效（本队实测）**：在 1× 昇腾 910C 双 die 上完成 Qwen3.5-0.8B 迁移，
单步训练耗时 **21,393 ms → 419.0 ms（51.1×）**；官方口径 50–100 步**窗口中位 419.0 ms**
（官方参考基线 431.3 ms，**同口径平价**；该数值绑定 2026-09-10 的运行时段，详见性能测试报告）。
精度上第 1 步 loss 与官方**逐位一致**（1.924621 = 1.924621），100 步逐点误差超 2% 的步数为 **0**；
裁决为 `NEEDS_EVIDENCE`（黄）——两道证据门（官方数据字节、样本序）按构造未闭合，**不宣称已验证/达标**。

## 二、需求与市场价值

### 2.1 用户需求贴合度

**行业痛点**：大模型结构迭代速度已远快于专用芯片的算子适配速度。以 Qwen3.5 引入的
GatedDeltaNet（线性注意力）、视觉 3D-Conv patch embedding 等新结构为例，它们在昇腾平台上
没有现成实现，传统迁移依赖专家逐行阅读源码、手工替换算子、逐层调试验证——
**不可复用、不可复现、不可规模化**。国产算力生态最缺的往往不是硬件，而是**把模型搬上硬件的工程效率**。

**我们的解法**：把迁移过程本身工程化。本队在该场景下完成了端到端验证：
面对一个昇腾生态尚无现成实现的新模型结构，从零环境到跑通 100 步训练、再到精度逐位对齐与
51 倍性能优化，全程由流水线驱动、每步产物落盘可复核。

### 2.2 市场价值及推广性

**可泛化**：迁移点识别规则外置为模型档案（`profiles/<model>.json`），AST 扫描器与流水线通用；
冗余设计使同一套流程可在**有卡/无卡、单卡/多卡、不同芯片型号、不同 CANN 与 torch 版本组合**
下自动选择执行路径——这解决了国产算力环境碎片化的现实问题。

**应用场景**：迁移后的 Qwen3.5-0.8B 接入工业"操作规范（SOP）判定"场景——
从监控画面判断操作手法是否合规（例如法兰螺栓是否采用对角交叉顺序紧固），
输出结构化 JSON（`compliant / step / issue / evidence / bbox / confidence`）。
该判定需要"语义 + 动作时序 + 常识推理"三重能力，传统 CV 小模型难以替代，
而昇腾边缘盒子/一体机的私有化部署形态天然适配工厂场景。

**推广模式**：① **开源** Skill 全量（含判定链与坑表）→ ② 向上游 MindSpeed-MM 提交 PR
（贡献 0.8B 示例配置与版本配对说明）→ ③ 面向昇腾生态 ISV 与工业质检厂商提供
"迁移即服务"的私有化落地。潜在合作对象包括昇腾生态解决方案商、工业视觉集成商与高校科研团队。

## 三、技术方案

### 3.1 功能架构与技术流程

Skill 采用**八阶段流水线**，上一步产物即下一步输入，全程证据落盘：

```
P0 环境探测 ─► P1 迁移点识别 ─► P2 方案与配置生成 ─► P3 算子/契约验证
   ─► P4 权重与数据准备 ─► P5 训练执行 ─► P6 性能基准 ─► P7 精度判定
   env.json      points.json     plan.md+cfg        ops.json
   assets.json   train.log       bench.json         verdict.json
```

各阶段职责：**P0** 探测 NPU/芯片/die 数/软件版本，决定执行路径与配置档；
**P1** 用 AST 静态解析建模源码，程序化输出迁移点矩阵（带行号与符号）；
**P2** 将迁移点映射为 MindSpeed-MM 落点，并按环境自动生成训练配置（几何/显存策略/算子后端）；
**P3** 验证算子 forward 与 shape 契约（有卡时增补 CPU↔NPU 数值一致性）；
**P4** 准备权重（HF→DCP）与数据（官方同源管线，含字节级校验）；
**P5** 执行训练并自动诊断常见故障；**P6** 按官方口径（50–100 步）产出性能数据；
**P7** 机器判定配置一致性与精度对齐，输出 `verdict_id` 并写入哈希链账本。

### 3.3 关键技术实现过程（创新点展开）

**创新点一：把"迁移范围"变成可审计的程序化输出。**
迁移对象不是人工拍脑袋圈定的，而是解析器对真实建模源码扫描所得的 49 处命中（带行号、带符号）。
这使得迁移范围可审计、可增量更新，也为后续适配其他模型提供了规则化基础。

**创新点二：用"几何可比性"而非"统计巧合"来证明精度对齐。**
我们发现：官方参考日志运行在 2 个 die 上、每 die 每步 4 个样本；若单卡一次跑 8 个样本，
每步的 batch 组成与官方物理上不同，逐点对比必然失真。经 `npu-smi` 实测确认本机为
**1 张 910C 双 die 卡**（单卡 2 芯片、合计 128GB），与官方拓扑一致，由此完整复刻官方并行几何。
结果是第 1 步（纯前向，学习率为 0）的 loss 与官方**逐位相同**——这同时证明了
权重、前 8 个样本的内容与顺序、算子数值实现三者均与官方一致，比任何统计指标都更强。

**创新点三：用"瓶颈量化"驱动优化，而非盲目调参。**
profiling 实测每步约 1.4 万个 kernel 发射、计算仅占 stage 时间的 23%，由此判定瓶颈是
**kernel 发射次数而非算力**，进而得到关键杠杆：kernel 数正比于 micro-batch 个数。
沿此思路完成八级优化，每级只改一个变量、收益均可在日志中复核。
过程中还得到三个反直觉结论：为旧小显存环境设置的省显存开关在 128GB 卡上纯属开销
（关闭后 step1 loss 逐位不变）；FSDP 预取深度加深反而变慢；`pregather` 可消除周期性长尾慢步。

**创新点四：让"精度是否达标"由机器裁决，而非人工宣称。**
判定链对 7+2 维配置做指纹比对，输出可达性级别与五态裁决，并以哈希链账本固化
`verdict_id`（账本任何篡改或重排都会在校验时被检出）。该链纯 CPU、**0-GPU 可完整复现**，
评委在无昇腾硬件的机器上也能复核我们的结论。
