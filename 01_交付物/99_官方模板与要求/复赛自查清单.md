## 一、总框架：一条主线 · 两条验证线 · 一个飞轮

### 1. 一条主线 —— Skill 五阶段流水线（初赛三环的直接升级）

| Phase | 名称 | 做什么 | 资产来源（已验证） | 本地可做 |
|---|---|---|---|---|
| P0 | env-probe | 探测 NPU/CANN/torch_npu，决定双轨（有卡轨A / 无卡轨B） | poc2 `probe_backend` | ✅ 已有 |
| P1 | analyze | AST 静态识别 4 类迁移点 → 迁移点矩阵 + MindSpeed 落点映射报告 | poc1_parse.py（对 v5.2.0 真源码命中 49 处） | ✅ 已有 |
| P2 | migrate | 按 fsdp2 迁移指南把迁移点映射为 MindSpeed-MM 补丁/配置 | 迁移指南规则化（待实卡迭代） | 规则表可先建 |
| P3 | verify | 算子矩阵 forward/shape 贯通 + CPU↔NPU 数值一致性核对 | poc2_npu_forward.py（4 类中 3 类真贯通） | ✅ 轨B 已有 |
| P4 | bench+scene | 性能基线→逐轮优化→数据落盘；工业场景契约冒烟 | poc3_scene.py + 新增 bench 模块 | 需实卡 |

### 2. 两条验证线
- **COCO 线（40 分主战场）**：官方 `dataset.rar` → 迁移前基线精度/性能 → Skill 迁移 → 迁移后精度/性能 → 喂报告 #3 #4。
- **工业线（创新+商业 40 分）**：迁移后 Qwen3.5-0.8B 接入 poc3 的 SOP 判定契约
  （语义+时序+常识推理，视觉 3D-Conv 看动作过程），端到端闭环出 JSON 判定。

### 3. 一个飞轮 —— 证据即交付
Skill 每跑一轮自动产出：全量 log（#5 数据源）＋ 每轮性能 JSON（#4 数据源）＋ 精度结果 JSON（#3 数据源）。
**拿到算力的第一天飞轮就要转**——原始日志事后补不出来。

### 4. 差异化故事线（答辩主打）
市面选手大概率"照官方指南手工改"；我们初赛已用 AST **程序化**识别出 4 类 49 处迁移点
（真解析 transformers v5.2.0 建模源码），复赛把这条人工路径封装成 Skill——
"输入模型 → 自动完成昇腾适配"的字面达成；双轨设计让**无卡评委机器也能复现** shape 等价证据（工程诚实性）。
